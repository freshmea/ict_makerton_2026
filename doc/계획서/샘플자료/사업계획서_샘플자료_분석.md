## 2. Pitch 자료 분석: 사업계획서의 설득 구조

### 2.1 전체 구성

핵심 구조는 **문제인식(Problem) → 실현가능성(Solution) → 성장전략(Scale-up) → 기업 구성(Team)**이다. 본문은 1~25장, 부록은 26~36장으로 분리해 발표 흐름과 질의응답 근거를 나눈다.

| 페이지 | 내용 | 사업계획서에서 배울 점 |
| --- | --- | --- |
| 1~2 | 아이템 한 문장 소개, 신청 정보, 목차 | 첫 장에서 누구를 위한 어떤 제품인지 알 수 있게 한다. |
| 3~5 | 한류·한국어 수요, TOPIK 필요성, 응시생 추이·시장규모 | 사회적 배경에서 구체적인 학습 수요로 좁힌다. |
| 6 | 학습자의 수준 파악 어려움, 기관·강사의 수기 채점·콘텐츠 제작 부담 | 사용자와 기관의 문제를 별도로 제시한다. |
| 7~14 | 솔루션 전환, 레벨테스트·취약점·맞춤 커리큘럼, 강의 관리·진행·자동 평가 화면 | 기능 목록을 고객 문제와 실제 사용 화면에 연결한다. |
| 15~16 | 콘텐츠 보유량과 경쟁 서비스 비교 | 비교 기준을 콘텐츠·지원언어·플랫폼·LMS·문제은행 등으로 구체화한다. |
| 17 | B2C·B2B 요금과 거래 흐름 | 사용자, 지불자, 제공 가치, 돈의 흐름을 한눈에 보여준다. |
| 18~19 | 연도별 성장 목표, 추진 일정, 개발·채용·마케팅 계획 | 고객 수·매출 목표를 실행 단계와 연결한다. |
| 20~21 | 정산 내역, 오픈베타·시범기관, 제휴·유학 네트워크 | 주장에 문서·화면·기관 사례를 붙인다. |
| 22 | 콘텐츠 개발, 마케팅, 시스템 개발의 사업비 사용 계획 | 예산이 어떤 사업 목표와 연결되는지 설명한다. |
| 23~24 | 대표·팀 역량, 협력사의 역할 | 경력 나열을 넘어 누가 무엇을 수행할지 보여준다. |
| 25 | 비전, 홈페이지·연락 정보 | 제품의 최종 가치를 다시 환기한다. |
| 26~36 | 부록 목차, 주관기관 적합성, 콘텐츠 개발진, 수요조사, 베타 결과, 비전·요금제·시장 근거 | 세부 증빙은 별도 부록으로 관리한다. |

### 2.2 핵심 비즈니스 논리

1. **고객의 이중 구조:** 학습자는 수준에 맞는 학습과 취약점 진단을 원하고, 교육기관·강사는 강의 운영과 채점 부담 완화를 원한다(6장).
2. **문제별 제품 대응:** 레벨테스트 → 취약 유형 분석 → 문제·강의·다국어 해설, 강의 개설 → 진행 → 학습 관리 → 자동 평가로 각각 연결한다(8~14장).
3. **차별화의 근거:** 콘텐츠 16,000개라는 보유량 주장과 경쟁 비교표를 제시한다(15~16장). 보유량이 교육 효과를 곧바로 입증하는 것은 아니므로 품질·활용 결과가 추가로 필요하다.
4. **수익 모델:** 자료상 B2C 월 15,000원, B2B 연 1,000,000원 등의 요금과 강의·첨삭 거래를 설명한다(17장). 부록에는 B2B Standard 연 100,000원 등 요금제 세분화가 있다(32장). 이는 자료 작성 당시 제안·설명이며 현재 판매 가격을 확인한 값이 아니다.
5. **실행 신뢰:** 정산·기관·네트워크·팀·협력사를 이어 제시해 실행 가능성을 설명한다(20~24장). 원본이 제시한 주장과 화면을 확인했으며 해당 계약·매출을 독립적으로 검증한 것은 아니다.

### 2.3 참고할 시각 표현

- 한 장에 핵심 메시지 하나를 크게 배치하고 제품 화면·차트·표로 설명한다.
- 소비자용 모바일 화면과 기관용 관리 화면을 나누어 이용 맥락을 구분한다.
- 문제를 제시한 뒤 해당 문제를 해결하는 화면을 보여주어 설명의 연결성을 높인다.
- 매출 목표 그래프, 추진 일정, 경쟁 비교표, 협력 관계표처럼 정보 성격에 맞는 표현을 사용한다.
- 부록으로 상세 증빙을 이동해 본문 흐름을 유지한다. 우리 계획서의 제출 분량은 별도로 지켜야 한다.

## 3. Google Docs 분석: AI로 아이디어를 구체화하는 과정

### 3.1 아이디어의 내용

AI 음악과 일반 음악을 함께 소개하는 인스타그램 큐레이션 계정을 운영하고, 창작자·레이블의 유료 홍보와 AI 음악 도구·음악 관련 서비스의 제휴 수익을 얻는 구상이다. 초기 제안에는 AI 음악과 일반 음악 7:3 구성, 15~30초 릴스, 퀴즈 콘텐츠, 제보 폼·DM 접수 등이 들어 있다. 모두 원문의 기획 제안이며 실제 운영 성과는 확인되지 않는다.

| 구성 요소 | 원문 내용 | 분석 |
| --- | --- | --- |
| 소비자 가치 | 새로운 음악 발견, 취향·상황에 맞는 추천, 작업용 BGM | 음악 발견의 불편을 구체적인 이용 상황으로 좁히는 방식이 유용하다. |
| 지불 고객 | 인디 뮤지션·AI 음악 제작자·레이블 | 팔로워와 광고비를 내는 고객을 분리해야 한다. |
| 수익원 | 릴스·스토리 유료 홍보, 제휴 링크·스폰서십 | 제휴 프로그램의 실제 존재·조건, 홍보 구매 의사는 별도 검증 대상이다. |
| 콘텐츠 운영 | 비주얼·하이라이트·짧은 설명, 정기 발행, 제보 접수 | 소규모 실험으로 콘텐츠 제작 시간과 반응을 확인할 수 있다. |
| 제안 KPI | 저장률 5% 이상, 공유율 3% 이상, 링크 클릭률 2% 이상 | 원문 목표값이다. 실측 성과·업계 기준이 아니며 분모와 기간도 정해야 한다. |
| 제안 단가 | 유료 음악 피칭 건당 10~20만원 | 검증 전 가격 가설이다. 고객의 실제 지불·재구매로 확인해야 한다. |

### 3.4 마케팅 흐름의 장점과 보완

원문은 네 가지 흐름을 제안한다.

1. 시각적 릴스 노출 → 3초 이상 시청 → 프로필 탐색 → 팔로우·알림 설정.
2. 상황별 카피 공감 → 음악·캡션 소비 → 다시 듣고 싶은 의도 → 저장.
3. 취향 표현 욕구 → 스토리 공유 → 지인 노출 → 신규 유입.
4. 협찬 콘텐츠 노출 → 호감·수용 → 아티스트 홍보 문의 또는 도구 제휴 전환.

행동 단계를 나눈 점은 유용하다. 다만 네 번째 흐름은 **리스너의 소비 경로와 광고주의 구매 경로를 섞는다.** 리스너는 발견 → 감상 → 저장·공유·링크 이동으로, 광고주는 사례 확인 → 문의 → 견적 → 계약·결제 → 게시 → 결과 리포트 → 재구매로 별도 설계하는 편이 명확하다. 퇴근 시간 18:30~20:00, 콘텐츠 7:3 비율, 디자인 형식 등은 정답이 아니라 비교 실험할 조건이다.

### 3.5 중요한 한계

- **'100명 설문', '심층 인터뷰 녹취록', '날데이터'라는 원문 표현을 실제 고객조사 증빙으로 인용하면 안 된다.** 문서 흐름상 AI가 생성한 인물과 응답이며, 실제 모집·동의·조사 일시·응답 원본이 확인되지 않는다.
- AI가 만든 응답을 다시 분석하고 타깃을 선정하는 과정은 같은 가정을 반복 강화할 수 있다. 가설 발굴에는 유용하지만 검증을 대체하지 못한다.
- 원문의 퍼센트·KPI·단가를 시장 수요·매출 실적으로 옮기지 않는다.
- 수치 설명 자체에도 불일치가 있다. AI 음악 수용 반응 설명은 '긍정적이거나 호기심 76%'라고 쓰지만 바로 아래 도식의 '긍정/호기심'은 64%, '중립/무관심'은 12%다. 중립을 긍정으로 합쳐 해석하지 않도록 원문 수치와 해석을 함께 점검해야 한다.
- 음악 사용 허락·광고 표시·제휴 조건에 관한 원문의 언급은 실행 가능한 조건을 확인한 증거가 아니다. 특히 광고 표기를 하단에 배치하라는 제안 등은 현행 기준을 별도로 확인한 뒤 실행해야 한다. 본 분석에서는 법적 적합성을 판단하지 않았다.
- 최종 슬라이드 생성 완료 문구만으로 실제 이미지·파일이 존재한다고 판단하지 않는다.

## 5. 300 Seconds 계획서에 적용할 방향

아래는 현재 저장소의 [300 Seconds 계획서](../300_Seconds_사업계획서.md)를 읽고 정리한 **후속 작성 제안**이다. 해당 계획서는 이번 작업에서 수정하지 않았다. 케이토픽의 성과나 음악 큐레이션의 가상 응답을 우리 팀 실적으로 사용하지 않는다.

### 5.1 표현과 구조

| 사업계획 항목 | 샘플에서 가져올 방식 | 300 Seconds에 적용할 내용과 필요한 근거 |
| --- | --- | --- |
| 문제인식 | 고객별 불편 분리 | 아이의 생각 시간이 끊기는 상황, 보호자의 지원 부담, 교육 운영자의 관리 필요를 실제 관찰·인터뷰로 구분한다. |
| 핵심 가치 | 한 문장 제품 정의 | '아이의 자율학습을 지켜주며, 요청받거나 합의한 순간에 짧게 돕는 책상 위 피지컬 AI 동반자'로 일관되게 설명한다. |
| 사용 흐름 | 문제→기능→화면 | 아이가 목표 선택 → 조용한 학습 → 도움 요청 → 힌트 1회 → 다시 기다리기 → 아이가 종료·기록 확인하는 장면을 제시한다. |
| 실현가능성 | 실제 기능 화면·검증 결과 | 음성 중단, 요청 범위 준수, 기억 갱신, 대기 동작을 각각 시연하고 하드웨어·통합 상태를 구분한다. |
| 차별화 | 공통 기준 비교표 | 일반 챗봇·학습 앱·책상 장치와 개입 방식, 음성 중단, 물리적 피드백, 기록·보호자 설정을 비교하되 상대 제품 확인 후 작성한다. |
| 사업화 | 사용자와 지불자·거래 흐름 | 아이, 보호자, 교육기관 중 누가 사용·구매·관리하는지 정하고 기기·구독·기관 도입 가격은 검증 전 가설로 둔다. |
| 추진계획 | 일정·예산·검증 단계 연결 | 시제품 구현 → 사용자 관찰 → 개선 → 사업화 실험으로 나누고 각 단계의 산출물·책임자·실제 견적을 연결한다. |
| 팀 역량 | 역할과 수행 근거 연결 | 기존 팀 역할에 구현 코드·디자인·시제품·시험 기록 등 실제 수행 근거를 붙인다. |

아이의 침묵·시선 변화만으로 집중 부족이나 심리상태를 단정하는 방향으로 확장하지 않는다. 기존 계획서의 아이 주도 선택, 대기, 중단 요청 존중 원칙을 유지한다.

### 5.2 가설을 실제 증거로 바꾸는 최소 조사안

다음 항목은 수행 완료 결과가 아닌 후속 조사 제안이다. 인원·일정·예산은 미정이다.

1. **실제 고객 인터뷰:** 보호자·아이·교육 담당자에게 최근의 구체적인 학습 상황, 도움 요청 방식, 원치 않는 개입, 도입 조건을 묻는다. 아이 대상 조사는 보호자 동의와 적절한 진행 절차를 준비한다.
2. **시제품 관찰:** 조용히 공부할 때의 대기, 힌트 요청, '내가 해볼게' 중단, 지난 기록 이어보기 장면을 관찰한다. 실제 장치·모의 화면·수동 대행을 구분해 기록한다.
3. **제품 동작 측정:** 중단 요청부터 발화 정지까지의 시간, 원치 않는 개입 횟수, 요청 범위 준수, 세션 완료·복귀 기록을 측정한다. 기준값·표본·기간은 사전에 정한다.
4. **구매 검증:** 구매자가 무엇에 돈을 내는지, 허용 가격과 도입 조건을 확인한다. 관심 표현과 실제 예약·유료 시험 도입을 구분한다.
5. **증거 대장:** 주장마다 출처, 수집일, 대상 수, 측정 조건, 결과 파일, '확인/가설/미정' 상태를 남긴다.

### 5.3 계획서 작성 전 확인 목록

- 고객 발언은 실제 인터뷰인지 AI 시나리오인지 표시했는가?
- 구현 완료·개발 중·확장 제안을 나누었는가?
- 시제품·화면 시연과 실제 장치 통합·현장 사용 결과를 구분했는가?
- 숫자에 출처·기준일·단위·분모·산식이 있는가?
- 일정·가격·예산·성과를 확정하지 않은 경우 '미정' 또는 '검증 예정'으로 남겼는가?
- 제출 양식의 분량을 지키면서 상세 증빙을 부록으로 분리했는가?
