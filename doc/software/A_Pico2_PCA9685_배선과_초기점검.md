# A 단계 시작 — Pico 2 · PCA9685 배선과 초기 점검

작성일: 2026-10-23, 한국 시간

상태: Rust 환경 구성·펌웨어 업로드·실제 USB/I2C 응답과 6채널 단회 순차 출력 명령을 확인했다. 최초 스캔은 VCC 제거 상태에서 응답이 없었으며, VCC 재연결 안내 뒤 0x41 응답을 확인했다. 실제 회전각·전압·정지 상태의 현장 측정은 별도다. 자세한 결과는 [RUN-20261023-01](test-results/2026-10-23/RUN-20261023-01.md)에 기록한다.

## 1. 현재 정보와 판정 범위

| 항목 | 근거와 상태 |
| --- | --- |
| 제어 보드 | 사용자 확인: Pico 2 / RP2350 |
| PWM 보드 | 첨부 사진에 SunFounder/PCA9685와 주소 패드·핀 표기 확인 |
| 주소 | A0 납땜 보고 뒤 실제 I2C 스캔에서7비트 `0x41` 확인. 함께 응답한0x70은 기본 ALLCALL 주소 |
| 외부 전원 | 사용자 보고: 7.2V→6V 컨버터 출력이 PCA 나사 단자V+/GND에 연결됨. 실제 극성·무부하/부하 전압은 계측 미확인 |
| 서보 | CLS6336HV 6개, CH0~CH5 순차 구동 확인. 500~2500µs에서 사용자 보고: 회전폭 증가, 걸림·이상음 없음. 실제 각도는 미계측 |
| 연결 순서 | 이번에는 서보 경로부터 준비. LED/눈/터치 항목이 통과한 것은 아님 |

사진만으로 선 전체의 목적지나 현재 전압을 확정하지 않는다. 전선 색·사진의 좌우보다 **보드 실크 VCC/V+/GND/SDA/SCL/OE**를 기준으로 다시 연결한다.

## 2. 전원 구분

```text
PC USB ────────── Pico 2
                    ├─ 3V3(OUT) ── PCA9685 VCC (로직)
                    └─ GND ─────── PCA9685 GND

외부 전원 7.2V (사용자 보고)
    └─ 컨버터 OUT+ 약 6V ─────── PCA9685 V+ (서보 전원)
       컨버터 OUT− ──────────── PCA9685 전원 GND
```

- **6V는 V+에만 연결한다. VCC에는 Pico의 3.3V를 연결한다.** PCA9685 IC의 VDD 정상 동작 범위는 2.3~5.5V이며, 보드의 V+는 별도 서보 전원 경로다.[W2]
- Pico는 처음에는 PC USB로만 전원을 공급한다. 외부 6V/7.2V를 Pico 3V3/VBUS/VSYS에 연결하지 않는다.
- 외부 서보 전원 GND와 Pico GND는 공통 기준으로 연결한다. 서보 전류의 복귀 경로는 컨버터–PCA 보드의 전원 배선으로 구성하고, Pico나 브레드보드·얇은 신호 점퍼를 통해 흘리지 않는다.
- 컨버터 출력은 극성 확인 후 PCA 보드의 전원 나사 단자 V+/GND로 연결한다. 핀 헤더 V+에 꽂힌 얇은 점퍼를 서보 6개 전체의 주 전원 경로로 사용하지 않는다.
- 6V 설정값과 실제 서보 부하 중의 전압 유지는 별도다. 먼저 1개에서 전압 강하·발열·리셋을 확인한다. 보유 컨버터의 실제 공급 전류는 미확정이다.

## 3. 1차 배선 — 서보 전원을 끄고 I2C만 확인

Pico의 USB와 외부 전원을 모두 끈 상태에서 연결한다. 첫 시험에서는 서보 커넥터도 빼 두고 외부 6V를 공급하지 않는다.

| PCA9685 표기 | 연결 대상 | Pico 물리 핀 번호 | 비고 |
| --- | --- | --- | --- |
| VCC | Pico 3V3(OUT) | 36 | 로직 3.3V |
| GND | Pico GND | 3 | 신호 기준 GND |
| SDA | Pico GP4 | 6 | I2C0 SDA |
| SCL | Pico GP5 | 7 | I2C0 SCL |
| OE | 초기에는 3V3(OUT)에 직접 연결 | 36에서 분기 | PWM 출력 비활성. GP12와 동시에 연결하지 않음 |
| V+ | 연결/인가하지 않음 | Pico와 연결하지 않음 | 1차 시험에서는 외부 서보 전원 OFF |

물리 핀 번호는 GP 번호와 다르다. 부품면을 위로 보고 USB를 위에 놓으면 왼쪽 위부터 물리 1번이다. 공식 핀맵에서 `GP4=6번`, `GP5=7번`, `3V3(OUT)=36번`, `GP12=16번`을 확인했다.[W1]

OE는 active-low 입력이다. HIGH에서는 PWM 출력이 비활성 상태가 되지만 서보 전원을 끊는 것은 아니다.[W2] 보드의 기존 OE 풀다운 저항값은 확인되지 않았으므로 임의의 10kΩ 풀업을 추가해 reset 중 HIGH가 보장된다고 가정하지 않는다.

SDA/SCL의 풀업이 VCC=3.3V에 연결되는지 확인한다. 외부 5V 풀업이나 이전 5V 로직 전원이 연결돼 있으면 제거하고 회로를 확인한 뒤 Pico와 연결한다. 기존 보드에 풀업이 있을 수 있으므로 저항을 무조건 추가하지 않는다.

### I2C 전원·주소 점검 순서

1. 외부 6V·서보 커넥터를 분리한다. 기존 연결선의 실크 위치를 다시 확인한다.
2. VCC/GND/OE를 위 표대로 연결하고 USB로 로직만 켠다. VCC–GND가 약 3.3V인지 확인한다. SDA/SCL의 유휴 HIGH가 3.3V 수준이고 5V/6V가 아닌지 확인한다.
3. 배선을 바꿀 때 다시 USB를 끄고 SDA/SCL을 연결한다. 최초 I2C 속도는 100kHz 후보로 둔다.
4. RP2350용 Rust 진단 펌웨어를 준비하고 업로드한다. 기존 펌웨어나 보드 LED 점등만으로 A-01을 통과시키지 않는다.
5. Pico가 실제 PCA9685에 응답을 받는지 확인하고 주소와 원본 로그를 RUN에 기록한다. 서보 PWM을 시작하는 명령은 아직 보내지 않는다.

주소 패드가 A0 하나만 연결됐다면 다음과 같다.

```text
기본 주소 0x40 + A0의 1 = 0x41
Rust 7비트 주소: 0x41u8
십진수: 65 (십진수 41과 다름)
```

다른 주소 패드도 연결됐다면 주소가 달라진다. 초기 상태의 ALLCALL 설정에 따라 `0x70`에도 응답할 수 있으므로 이것을 두 번째 물리 보드로 단정하지 않는다.[W2] 어느 주소에도 응답하지 않으면 VCC/GND·SDA/SCL·실제 납땜 상태부터 확인한다.

## 4. 2차 배선 — 서보 1개 시험 준비

아래는 I2C 응답을 확인한 뒤 진행한다. 자동 왕복 sweep이나 6축 동시 구동부터 시작하지 않는다.

1. USB와 외부 6V를 모두 끈다.
2. **OE–3V3 직결선을 완전히 제거**하고 OE를 `GP12 / 물리 16번`으로 옮긴다. 직결 상태에서 GP12까지 연결해 LOW를 출력하면 안 된다.

   **PCA VCC–Pico 36번(3V3 OUT) 전원선은 계속 유지한다.** 제거 대상은 OE에 연결했던 직결선 하나이며, VCC 전원선과는 별개다. 최종적으로 아래 두 선이 동시에 필요하다.

   ```text
   Pico 36번 3V3 OUT ───────── PCA VCC   ← 항상 필요한 로직 전원
   Pico 16번 GP12 ──────────── PCA OE    ← 펌웨어가 제어하는 출력 허가
   ```

3. Rust 펌웨어가 GP12를 먼저 HIGH로 초기화하고, 전체 채널 OFF·설정 확인을 마친 뒤 명시적인 시험 명령에서만 OE를 LOW로 바꾸도록 한다.
4. 서보 1개만 보드 실크 `CH0`의 3핀에 연결한다. 사진의 꽂힌 위치를 채널 0으로 추정하지 않는다.
5. PCA 로직은 USB/3.3V, 서보 V+는 외부 컨버터 6V로 분리 공급한다. 전원 인가 전에 V+/GND 극성을 계측한다.
6. 기구 하중을 분리하거나 지지하고, 준비된 펄스 범위 안에서 한 번의 제한된 동작을 명령한다. 혼·관절이 닿거나 멈춰 버티는 상태를 만들지 않는다.
7. 실물 움직임·전원 전압·정지·USB 단절을 기록한다. ACK나 PWM 레지스터 반영은 실제 각도 도달의 증거가 아니다.

| 일반적인 서보 선색, 현품 확인 필요 | PCA9685 채널 핀 |
| --- | --- |
| 갈색/검정 | GND |
| 빨강 | V+ / 6V 서보 전원 |
| 노랑/주황 | PWM / 신호 |

선색만으로 확정하지 말고 서보와 보드의 실제 표기를 확인한다. 서보의 사용 가능한 펄스·중립·방향·6V 동작 조건은 개체별 검증 대상이다. 이전 로봇 예제의 460~2440µs·최대각도·오프셋을 이 시제품에 그대로 적용하지 않는다.

OE=HIGH는 무조건 토크 유지나 기계적 고정을 보장하지 않는다. reset 중 OE 상태, Stop 시 토크 유지/출력 차단 정책은 기구 결합 전에 별도로 검증한다. 첫 통신 시험을 6V OFF로 하는 이유도 이 제한 때문이다.
