# 눈 LED 상시 표시와 20초 자동 표정

2026-10-25 KST. 기본 눈을 계속 켜고, 버튼·기기 활동·관찰 자료의 행동과 키워드를 이용해 20초마다 표정을 선택한다. 브라우저가 닫혀 있어도 대시보드 서비스가 실행하며, 표정 선택을 위한 추가 AI 요청은 없다.

## 선택과 표시

- 처음 연결하면 눈 전용 `servo_enabled=false`, `matrix_installed=true`, 밝기 1로 시작한다. 팔·서보 동작은 자동으로 실행하지 않는다.
- 최근 상황이 뚜렷하지 않으면 자연스러운 대기 표정 중 하나를 무작위로 선택한다. 같은 표정이 다시 선택되어도 점등을 유지하며 불필요한 Stop·Arm을 반복하지 않는다. 깜빡임 같은 기존 애니메이션은 유지한다.
- 우선순위는 Live 준비·대화 → 최근 버튼 → 기기 음성·활동 → 관찰 행동·키워드 → 기본 눈이다. 20초마다 새로 선택하고 그 사이에는 선택한 표정을 유지한다. 짧은 버튼 입력·안내음·시험 완료는 다음 선택까지 기억하며 같은 이벤트를 반복 소비하지 않는다.
- 관찰은 두 카메라에서 각각 최근 2분 이내의 최신 성공 표본을 사용한다. 중복 생략 표본은 `duplicate_of`의 내용과 최신 촬영 시각을 연결한다. 실패·미래·오래된 기록과 명료도 0.5 미만은 사용하지 않는다. 브라우저의 과거 날짜 검색 결과가 현재 표정을 덮어쓰지는 않는다.

| 근거 | 표정 예 |
| --- | --- |
| Live 준비 / 대화 | 궁금해 / 방긋 미소 |
| 버튼 1~6 | 방긋 미소 / 궁금해 / 자신감 / 반짝반짝 / 흥얼흥얼 / 활짝 웃음 |
| 음성·소리 재생 / 장치 시험 완료 | 흥얼흥얼 / 잘했어 |
| 필기 / 읽기 / 키보드 입력 | 자신감 / 아래 보기 / 굳은 결심 |
| 휴대전화·물건 다루기 / 음식·음료 | 다양한 호기심 시선 / 여유로움 |
| 음악 / 질문·계산 / 그림·미술 | 흥얼흥얼 / 다양한 호기심 시선 / 반짝반짝 |
| 선택에 사용할 최근 근거 없음 / 사람이 보이나 구체적 활동 없음 | 다양한 대기 표정 |

키워드는 고정된 카탈로그 ID로만 매핑한다. 관찰 문구를 명령으로 실행하거나 임의의 장치 명령으로 바꾸지 않는다. 이는 기기의 반응 연출이며 사람의 감정·내적 집중 상태를 판정하는 기능이 아니다.

### 2026-10-25 반복 표정 개선

물음표가 있는 `curious`는 기존에 `handling_objects`, `phone_use`, 질문·계산 키워드에도 고정되어 있었다. 사용자에게 판단 불가 표시처럼 보이며 같은 모양이 반복된다는 피드백을 반영했다.

- **대기 9종**: 기본 깜빡임, 왼쪽·오른쪽·위 보기, 양쪽 윙크 각각, 눈 벌리기, 눈 모으기, 방긋 미소. 근거 부족·오래된 관찰·조회 실패 또는 사람이 보이지만 구체적 활동이 없을 때 사용한다.
- **호기심 6종**: 궁금해, 왼쪽·오른쪽·위 보기, 눈 벌리기, 눈 모으기. 일반적인 물건 다루기·휴대전화·질문 키워드 반응에서 물음표가 계속 고정되지 않게 한다.
- 위 무작위 선택에서는 **직전 세 번의 자동 표정을 제외**한다. 세 후보 이력이 있어도 각 그룹에 후보가 남는다. 20초 간격은 유지하고 선택 사이에는 기존 깜빡임·윙크 애니메이션을 계속 재생한다.
- 명확한 읽기·필기·키보드 입력, Live 연결/대화, 직접 누른 버튼, 기기 음성·시험 완료 피드백은 해당 상황의 기존 표정을 유지한다.

이 변경은 기존 50개 카탈로그를 사용한다. 사람의 감정 판단이나 추가 AI 호출을 늘리지 않는다. 수동 표정 우선권, 전체 정지 잠금, 서보·장치 시험 우선권도 유지한다.

후속 검사: 로컬 관련 77개·Nano Python 3.8의 자동 선택/기존 눈 재생 28개가 통과했다. 실제 `handling_objects` 관찰에서 눈 벌리기 → 오른쪽 보기가 20.767초 간격으로 선택된 것을 상태 API로 확인했다. 최종 상태는 자동 모드·상시 표시·관찰 수집 켜짐, 서보 OE HIGH·pose 비활성이었다. 긴 연속 측정은 서비스 재시작·HTTP 연결 중단으로 제한되었고, 최종 선택 이력에서 약 20.1~20.4초 주기를 확인했다. ## 수동 제어와 정지

**표정 시험**은 기존 3/5/10초 동안 자동 선택보다 우선한다. 끝나면 소등하지 않고 자동 표정으로 복귀한다. 서보 제어·장치 진단이 시작되면 해당 소유자에게 양보하고 끝난 후 복구한다. 서로 다른 장치 소유자를 중간에 Stop하거나 재-Arm하지 않는다.

**표정 끄기·전체 정지**는 자동 모드도 중지한다. `자동 표정 켜기`를 눌러 다시 시작할 수 있다. 자동 모드의 사용자 선택은 기존 SQLite `settings.automatic_eyes_enabled`에 보존한다. 서비스 종료 때는 정지하고, USB 재연결 후에는 이전 작업을 재전송하지 않고 새 작업으로 시작한다.

API는 기존 표정·정지 API와 `POST /api/pico/expressions/automatic`(`{"enabled":true/false}`)을 사용한다. 동일 Origin·CSRF 검사는 그대로 적용된다. `/api/status.eye_expression`은 `persistent`, `mode`, `automatic`에 선택 근거·관찰 ID·선택 횟수·다음 선택까지의 시간·대기 상태를 제공한다.

## 검증과 배포

로컬 관련 검사 **81개**, Nano의 Python 3.8에서 자동 선택 14개·기존 눈 재생 11개·관찰 DB 37개·서보 12개, 총 **74개가 통과**했다. 20초 이전 재선택 없음, 반복 선택 시 Stop·Arm 없음, 버튼 이벤트의 세션·신선도 검증, 짧은 활동 기억, 수동 종료 후 복귀, 정지 중 늦은 Arm 차단, 진단·서보 우선권을 검사했다.

실제 Pico는 **42초 연속 관찰** 동안 상시 표시 상태를 유지했고 선택 간격은 **20.648초·20.181초**였다. 이때 최근 관찰의 `책` 키워드로 `look-down`을 선택했다. `happy` 3초 수동 표시 후 자동 표정으로 복귀하고, 전체 정지 뒤 자동 모드가 꺼진 채 유지되는 것을 확인했다. 검증 종료 시 자동 모드를 다시 켰다. `Applied.kind=3`, `armed=true`, `oe_high=true`, `pose_active=false`를 확인했으며 서보 이동 명령은 보내지 않았다. 버튼의 실제 실물 누름은 이번 검사에 포함하지 않았고, 세션에 맞는 Touch 이벤트 처리는 모의 검사로 확인했다.

실제 브라우저에서 `궁금해 · 계속 표시 중`과 `관찰 행동 · handling_objects` 선택 근거, 자동 토글의 `aria-pressed=true`, 수동 진단 버튼 사용 가능을 확인했다. 모바일 390px 가로 넘침과 스크립트 오류는 없었다. 반복 상태 안내는 내용이 바뀔 때만 갱신한다.
