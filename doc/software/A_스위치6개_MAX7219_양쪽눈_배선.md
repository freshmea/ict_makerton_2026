# A 단계 — 터치 6개와 MAX7219 양쪽 눈 배선

작성일: 2026-10-23, 한국 시간. 사용자가 마지막 터치·매트릭스 시험까지 완료했다고 확인했다. 이 문서는 그 사용자 확인을 기록하고, 새 [통합 펌웨어](../../firmware/pico2-device-bench/README.md)에 맞는 배선을 고정한다. 기존 개별 이미지의 시험 완료가 새 통합 이미지의 업로드·USB·실물 동작 완료를 뜻하지는 않는다.

## 1. 연결할 핀

Pico의 USB를 위로 놓고 부품면을 본 물리 핀 기준이다. 전선 색보다 모듈의 실제 `IO/VCC/GND`, `DIN/DOUT/CLK/CS` 표기를 따른다. [공식 Pico 핀맵](https://datasheets.raspberrypi.com/pico/Pico-2-Pinout.pdf)

| 대상 | Pico GPIO | 물리 핀 | 비고 |
| --- | --- | --- | --- |
| SW1 IO | GP6 | **9** | 터치 상태 1번 |
| SW2 IO | GP7 | **10** | 터치 상태 2번 |
| SW3 IO | GP8 | **11** | 터치 상태 3번 |
| SW4 IO | GP9 | **12** | 터치 상태 4번 |
| SW5 IO | GP10 | **14** | 터치 상태 5번 |
| **SW6 IO** | **GP11** | **15** | **기본 로컬 진단 선택/정지** |
| 터치 VCC 6개 | 3V3(OUT) | **36** | 3.3V 동작을 지원하는 모듈인지 확인 |
| 터치 GND 6개 | GND | 3 등 | Pico와 공통 |
| 첫 MAX7219 CLK | GP18 | **24** | SPI0 SCK, mode 0, 1MHz |
| 첫 MAX7219 DIN | GP19 | **25** | SPI0 TX |
| 두 MAX7219 CS/LOAD | **GP20** | **26** | GPIO CS를 두 모듈에 공통 연결 |
| 두 MAX7219 VCC | 외부 5V | Pico GPIO에 연결하지 않음 | 모듈 전류 포함해 공급 용량 확인 |
| 두 MAX7219 GND | 외부 전원 GND + Pico GND | 공통 | LED 전류 복귀는 전원 배선으로 구성 |

기존 **PCA SDA=GP4/6번, SCL=GP5/7번, OE=GP12/16번**은 유지한다. 양손 NeoPixel은 GP16/21번과 GP17/22번이므로 매트릭스 CS는 GP17이 아닌 **GP20/26번**이다. 전체 전원 분기는 [핀 배정·전원 문서](Pico2_핀배정_및_전원.md)를 따른다.

## 2. 터치 6개

```text
Pico 3V3 OUT(36번) ─── 3.3V 지원 터치 VCC × 6
Pico GND ──────────── 터치 GND × 6
GP6/7/8/9/10/11 ───── 각 SW1/2/3/4/5/6 IO
```

확인된 형태는 IO/VCC/GND 세 단자 모듈 6개다. **TTP223 등 특정 칩으로 확정하지 않는다.** 현품의 3.3V 전원 지원, IO HIGH 전압, 순간/토글 모드와 활성 극성은 직접 확인해 기록한다. 5V 전원을 쓰는 모듈의 5V IO를 Pico에 직결하지 않는다.

통합 코드는 각 입력에 **PullNone**을 적용하며 GPIO HIGH를 raw bit 1로 읽는다. 기본 눌림은 HIGH이고 `touch_active_low_mask`의 해당 비트를 1로 하면 그 입력만 LOW=눌림으로 바뀐다. 이 설정은 극성을 바꾸며 내부 pull을 추가하지 않는다. 비트0=SW1, …, 비트5=SW6이다. 예를 들어 SW6만 active-low면 마스크는 `32`다.

모듈 IO가 안정적으로 HIGH/LOW를 구동하는지 확인한다. 미연결·부동 핀의 변화는 실제 터치로 판정하지 않는다. 단순 접점 스위치로 교체할 경우 외부 pull 등 전기 구성을 별도로 정해야 하며, 현재 PullNone 배선에 두 선만 임의로 연결하지 않는다. 토글형 모듈의 IO HIGH 지속 시간은 실제 손가락 접촉 시간과 다를 수 있다.

입력은 5ms마다 읽고 30ms 안정된 전환을 눌림/해제로 인정한다. USB 상태에는 여섯 입력의 raw/pressed mask, 현재 hold 시간·500ms interval count, 마지막 release 결과, 별도 2초 고정창 안의 press 횟수가 포함된다. 정확한 의미는 [공유 프로토콜](../../crates/pico-device-protocol/README.md)을 따른다.

## 3. MAX7219 모듈 2개 직렬 연결

**Pico와 먼저 연결되는 모듈을 왼눈, 그 다음 모듈을 오른눈**으로 정의한다. 모듈을 놓은 방향이 아니라 실제 DIN→DOUT 연결 순서로 구분한다.

```text
Pico GP19 TX ── [레벨 변환] ── 왼눈 DIN
                               왼눈 DOUT ───────── 오른눈 DIN

Pico GP18 CLK ─ [레벨 변환] ── 왼눈 CLK ─────────── 오른눈 CLK
Pico GP20 CS ── [레벨 변환] ── 왼눈 CS/LOAD ─────── 오른눈 CS/LOAD

외부 5V ───────────────────── 왼눈 VCC ─────────── 오른눈 VCC
외부 GND + Pico GND ────────── 왼눈 GND ─────────── 오른눈 GND
                                                   오른눈 DOUT: 미연결
```

MAX7219는 DIN을 CLK 상승 에지에서 읽고 LOAD 상승으로 명령을 반영한다. 소프트웨어는 MSB first, 32비트를 한 CS 구간에 보내며 **먼 오른눈 명령 16비트 → 가까운 왼눈 명령 16비트** 순서다. 두 모듈은 CLK와 CS를 공유한다. 모듈에 인쇄된 입력/출력 단자를 확인하고 첫 모듈의 DOUT을 Pico에 연결하지 않는다. [제조사 MAX7219/MAX7221 데이터시트](https://www.analog.com/media/en/technical-documentation/data-sheets/MAX7219-MAX7221.pdf)

5V MAX7219의 HIGH 입력 최소값 3.5V에 비해 Pico 출력은 3.3V이므로, 제품 배선에는 **74AHCT125 등의 5V 버퍼 3채널**로 CLK·DIN·CS를 변환하는 구성을 권장한다. 기존 3.3V 직결에서 시험이 끝났다는 사용자 확인은 그 실물 조건의 결과이며 데이터시트 보장은 아니다. NeoPixel과 MAX7219의 문턱 조건도 각각 확인한다. AHCT와 AHC를 혼동하지 않는다. 버퍼 전원 핀 가까이 0.1µF, MAX7219 전원 가까이 0.1µF와 10µF를 두며 모듈에 이미 실장된 부품을 먼저 확인한다. [Nexperia AHCT125](https://assets.nexperia.com/documents/data-sheet/74AHC_AHCT125.pdf)

두 모듈을 가까이 놓으면 전원 단자를 이어 사용할 수 있지만 모듈·점퍼·커넥터의 전류 용량을 확인한다. 서보 전원 6V를 매트릭스 VCC에 연결하지 않는다. 눈 2개와 NeoPixel을 같은 5V 전원으로 쓰면 총 부하를 합산한다.

## 4. 초기화와 단회 표시

통합 코드는 display-test=0을 먼저 적용하고 shutdown 상태에서 행을 지운다. decode=0, scan-limit=7, intensity=1로 설정한 뒤 검사 중에만 표시를 켠다. display-test=1은 일반 밝기·shutdown 설정을 덮어쓰므로 기본 진단에 사용하지 않는다. 제조사 문서의 전원·초기화 조건을 근거로 한 설정이다.

눈 단회 검사는 약 9.8초 동안 다음 순서로 진행한다.

| 순서 | 표시와 확인 목적 |
| --- | --- |
| 1 | 가까운 왼눈 L, 반대쪽 꺼짐: 좌우 체인 식별 |
| 2 | 먼 오른눈 R, 반대쪽 꺼짐: 오른눈 연결 식별 |
| 3 | 두 눈의 8행 순차 표시: 행 누락 확인 |
| 4 | 두 눈의 8열 순차 표시: 열 누락 확인 |
| 5 | 양쪽이 서로 다른 checker, 눈 패턴: bitmap 구분 |
| 종료 | blank + shutdown: 두 눈 소등 |

모듈의 실제 PCB·매트릭스 장착 방향에 따라 글자·행·열이 뒤집혀 보일 수 있다. 우선 실제 방향과 체인을 기록한 뒤 필요한 회전/반전 보정을 후속 설정으로 정한다. 현재 코드에는 임의의 회전 보정을 적용하지 않았다.

## 5. SW6으로 검사 선택

기본 SW6은 **GP11 / 물리 15번**이다. 대기 상태에서 안정된 눌림부터 측정한 시간을 500ms로 나눈 정수 count를 **놓을 때** 읽어 검사 하나를 시작한다. 이 count는 2초 시간창 안의 여러 번 눌림 횟수와 다르다.

| hold count | 기본 눌림 시간 | 선택 |
| --- | --- | --- |
| 0~1 | 1초 미만 | 양쪽 매트릭스 |
| 2 | 1.0초 이상~1.5초 미만 | 왼손 NeoPixel |
| 3 | 1.5초 이상~2.0초 미만 | 오른손 NeoPixel |
| 4 | 2.0초 이상~2.5초 미만 | 서보 6개 순차, 작은 명령 범위 |
| 5 | 2.5초 이상~3.0초 미만 | 눈 → 왼손 → 오른손 → 서보 |
| 6 이상 | 3초 이상 계속 누름 | 전체 Stop, 놓아도 검사 시작하지 않음 |

검사 중 SW6의 새 눌림은 정지를 요청하고 그 해제는 소비한다. 부팅·설정 변경·Stop·새 USB Hello 등으로 취소된 hold는 raw 입력을 안정적으로 30ms 해제한 다음의 새 누름부터 수락한다. 부팅·USB 재연결만으로 검사를 시작하지 않는다. `local_tests_enabled=false` 또는 `test_switch=0`이면 로컬 선택을 끈다.

Nano가 상태를 받고 있는 동안에도 idle의 로컬 검사를 허용한다. 활성 세션이 있으면 200ms KeepAlive와 1초 lease에 종속되고, Nano 연결 종료·lease 만료로 정지한다. USB 없이 시작한 로컬 검사도 유한하게 끝난다. 서보 진단은 기본 명령값 `90→80→100→90`, 1000~2000µs 범위이며 실제 회전각을 계측한 값은 아니다.

## 6. 점검과 기록

사용자 확인: 마지막 터치·매트릭스 시험 완료. 아래 항목은 통합 이미지에서 다시 확인할 체크리스트이며 지금 통과 처리하지 않는다.

- [ ] 전원을 끈 상태에서 SW1~SW6 IO와 물리 핀을 도통 확인한다. SW6=15번, OE=16번을 구분한다.
- [ ] 터치 VCC–GND와 IO HIGH/LOW를 측정하고 품번·순간/토글·극성을 기록한다.
- [ ] 각 입력을 하나씩 눌러 raw/pressed 비트와 `Touch.index` 1~6의 대응을 확인한다. 동시 입력·해제·debounce도 확인한다.
- [ ] 가까운 왼눈 L/먼 오른눈 R, 8행·8열·checker·종료 소등을 실제로 관찰한다. 뒤집힘이 있으면 방향을 기록한다.
- [ ] SW6 선택·활성 중 정지·누른 채 부팅·Stop 후 해제에서 원치 않는 재실행이 없는지 확인한다.
- [ ] USB 상태 구독 중 SW6 검사와 연결 종료·lease 만료 정지를 확인한다. USB 없는 유한 로컬 검사 결과도 따로 남긴다.
- [ ] 부하 전원 전압·발열·USB 단절 여부와 **30개 초과 NeoPixel 추가 전원 실부하 TODO**를 함께 점검한다.

빌드와 명령은 [통합 진단 실행 문서](Pico_Nano_USB_통합_진단.md), [Nano/PC 도구](../../tools/pico-device-bench/README.md)를 따른다. `Ack`·`Status`·완료 이벤트는 소프트웨어 보고다. 실제 눌림·표시·소등·회전 관찰과 전압 계측은 [시험 기록 양식](시험_기록_양식.md)에 별도로 남긴다. 본 문서 작성 중 실장치 접근·업로드·전원 변경은 수행하지 않았다.
