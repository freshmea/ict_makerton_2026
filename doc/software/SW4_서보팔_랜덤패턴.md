# SW4 짧은 누름 · 서보 1~4번 팔 패턴

후속 확대 요청: 모든 패턴의 진폭을 **기준각 ±6° → ±12°(왕복 전체 폭 24°)**로 2배 확대했다. 약 9초의 동작 시간을 유지하며 최대 명령 속도는 24°/초다. 확대 버전 배포·검사는 [double-swing 기록](dashboard-check/2026-10-25/sw4-arms/double-swing/)을 따른다. 아래 최초 실물 확인은 확대 전 버전의 기록이다.

2026-10-25 **Nano/Pico 적용 완료**. Nano에서 펌웨어 23개·프로토콜 13개·브리지 13개·대시보드 41개, 총 90개 검사를 통과했다. 기존 4MiB flash 백업, 새 이미지 쓰기·읽기 검증과 대시보드 복구를 완료했다. 실제 SW4 입력에 따른 CH0~CH3 목표 변화·약 9초 후 기준 복귀·OE HIGH·faults 0·SW3 조명 유지까지 수집했다. 실제 물리 회전각·10종 전수 관찰은 별도이며 [검증 기록](dashboard-check/2026-10-25/sw4-arms/)을 따른다.

사용자가 실물 4번을 눌러 **“서보 1~4번 모두 정상 동작”**을 확인했다. 이는 사용자 움직임 확인이며 각도 센서 계측과 구분한다.

SW4는 GP9/물리 12번이며 **서보 1~4번=CH0~CH3**을 제어한다. 물리 16번/GP12는 서보 OE이므로 스위치 배선과 구분한다. 기존 SW3 조명과 독립적으로 동작한다.

버튼을 짧게 누르면 30ms 디바운스 후 다음 20ms 출력 tick에서 10종 중 하나를 무작위로 선택한다. “사번” 음성·유지 비프음은 별도 경로로 계속 동작하며 음성 완료나 버튼 해제를 기다리지 않는다. 길게 눌러도 한 번만 선택하고, 다시 누르면 직전과 다른 패턴으로 부드럽게 전환한다.

| 번호 | 패턴 | 서보 1·2·3·4의 목표 변화 |
|---|---|---|
| 1 | 함께 흔들기 | 네 축 동시 왕복 |
| 2 | 좌우 번갈아 | 1·2와 3·4를 반대 방향으로 왕복 |
| 3 | 짝 비틀기 | 1·3과 2·4를 반대 방향으로 왕복 |
| 4 | 정방향 물결 | 1→2→3→4 순서 |
| 5 | 역방향 물결 | 4→3→2→1 순서 |
| 6 | 바깥·안쪽 | 1·4와 2·3을 번갈아 왕복 |
| 7 | 대각선 물결 | 1·4, 2·3을 각각 반대 방향으로 왕복 |
| 8 | 계단 올리기 | 네 축을 하나씩 올렸다가 차례로 복귀 |
| 9 | 작은 파닥임 | 짝 비틀기의 절반 진폭 |
| 10 | 숨쉬는 팔 | 네 축이 중간각을 거쳐 서서히 왕복 |

좌우·대각선은 논리적인 축 조합 이름이다. 실제 팔의 설치 방향·링크 구조에 따른 물리 동작은 실물 확인이 필요하다.

## 범위와 정지

- 한 번에 약 **9초** 실행하고 기준각으로 복귀한 뒤 CH0~CH3 PWM을 끄고 OE HIGH로 출력을 해제한다. 계속 움직이려면 다시 누른다.
- 기준각 대비 **최대 ±12°**, 속도 **최대 24°/초**, 전체 목표각은 0~180°로 제한한다. 중간 재선택에서도 기존 기준각을 유지해 반복 누름에 따른 각도 누적을 막는다.
- 각 축의 마지막 PWM 명령각을 기억해 새 Arm과 SW4의 시작각으로 사용한다. 대시보드의 완료 목표각을 `servo-targets.json`에 저장하고 USB 세션마다 출력 없는 `SeedServoPositions` 명령으로 복원한다. **1~4번 참조각이 모두 알려지기 전에는 SW4가 모터를 켜지 않는다.** 위치 센서 측정값은 아니며 실제 각도나 기구 간섭을 보장하지 않는다.
- 펄스 폭은 기존 `DeviceConfig`의 `servo_min_us`/`servo_max_us`를 사용한다. 현재 프로필은 500~2500µs/약 50Hz이다. SW4는 invert_mask=0을 사용한다.
- 5·6번(CH4·CH5)의 목표각과 PWM 이동 명령을 갱신하지 않는다. 첫 초기화와 공용 Stop에서는 기존처럼 PCA9685 전체 출력을 차단한다.
- 호스트가 서보용 Arm을 소유하거나 진단 시험 중이면 SW4를 무시한다. 수동 이동·GPT Decisions는 기존 Stop 후 Arm 경로로 버튼 동작을 선점한다.
- PCA fault, USB 단절/keepalive 만료, Stop, watchdog, 새 USB 세션에서 취소한다. 누른 채로 정지된 입력은 실제 해제 후 다시 눌러야 한다.
- SW4만으로 NeoPixel·눈을 지우지 않으며 완료 시에도 해당 출력을 유지한다. 공용 Stop은 모든 출력을 정리한다.

## 코드와 검증

- [arm_patterns.rs](../../firmware/pico2-device-bench/src/arm_patterns.rs): 10종 키프레임, 시간 보간, 랜덤 재선택, 범위 제한.
- [application.rs](../../firmware/pico2-device-bench/src/application.rs): 단일 I2C 소유자에서 PWM 실행·완료 해제.
- [main.rs](../../firmware/pico2-device-bench/src/main.rs): 실제 SW4 입력, fault/세션 검사, 정지 취소, 마지막 명령각 추적.

검사는 10종 전 범위·속도·종료 복귀·5/6번 목표 보존, 1,000회 연속 재선택과 기준각 누적 방지, SW3/SW4 입력 분리·짧은 누름·접점 튐·길게 유지·정지 세대 변경·양쪽 입력 극성, 기존 정지·눈·서보 검사를 포함한다.
