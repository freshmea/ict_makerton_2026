# 시험 기록 양식

이 파일은 빈 양식이다. 실행 결과가 아니다. 복사해 `test-results/YYYY-MM-DD/RUN-YYYYMMDD-NN.md`로 저장하고 [개발 단계 및 점검표](개발_단계_및_점검표.md)의 작업 ID와 연결한다. 경로는 시험을 수행할 때 생성한다.

## 1. 기본 정보

| 항목 | 기록 |
| --- | --- |
| RUN ID | 작성 예정 |
| 작업 ID | 작성 예정: 예 A-04, B-05, C-04 |
| 제목·목적 | 작성 예정 |
| 수행자·점검자 | 미정 |
| 시작·종료 시각 / 시간대 | 작성 예정 / Asia/Seoul |
| 검증 범위 | 미정: 빌드 / 모의 시험 / 실물 단독 / 실물 통합 |
| 결과 | 미점검: 진행 중 / 통과 / 실패 / 차단 / 해당 없음 |
| 직전 RUN / 결함 ID | 작성 예정 |

해당 없는 항목은 이유와 함께 해당 없음으로 적는다. 미확인 값을 예시 숫자로 채우지 않는다. 소스 버전만 기록하지 말고 실제 실행한 파일과 설정도 식별한다.

## 3. 선행 조건과 재현 절차

선행 RUN/gate, 부팅·Arm·조립·네트워크 상태, 시험 중 사용할 장치 범위를 기록한다.

| 순서 | 명령/조작과 입력 | 기대 결과·판정 기준 | 실제 결과 | 증거 |
| --- | --- | --- | --- | --- |
| 1 | 작성 예정 | 작성 예정 | 미검증 | 작성 예정 |

수행하지 않은 단계를 수행한 것처럼 적지 않는다. 코드 블록에는 정확히 실행한 명령을 붙이고, raw log 원본을 별도로 보관한다.

| --- | --- | --- | --- | --- | --- |
| 작성 예정 | 작성 예정 | 미정 | 작성 예정 | 미검증 | 미점검 |

숫자를 측정하지 않았다면 미검증으로 둔다. 서로 다른 장치의 단조 시각을 직접 빼지 않는다. ACK 시간·task 주기·프레임 처리 시간·물리 출력 종료 지연을 구분한다. 기준을 정하지 않았다면 측정만 보고하고 성능 통과로 표시하지 않는다.
