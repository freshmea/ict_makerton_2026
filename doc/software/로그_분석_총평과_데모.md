# 로그 분석 · 시간별·일별·월별 총평

2026-10-25 Nano 운영 대시보드에 반영했다. 메인 화면의 **로그 분석**에서 열거나 다음 주소로 접근한다.

- [실제 기록 분석](http://192.168.184.76:8000/analytics?source=real)
- [데모 보기](http://192.168.184.76:8000/analytics?source=demo)

주소는 같은 공유기에서 접근하는 현재 Nano IP다. 공유기나 DHCP가 바뀌면 대시보드 주소를 확인한다.

## 화면과 사용 방법

시간별·하루·한 달을 선택하고 날짜와 이전/다음 버튼으로 이동한다. 선택 구간의 총평, 보이는 학습 행동, 자리비움, 긍정·차분 감정 단서, 데이터 커버리지를 표시한다. 시간별 화면은 선택 시간과 앞선 다섯 시간을 함께 보여준다. 하루는 24시간, 한 달은 날짜별 흐름을 보여준다.

**하루하루, 한 달 한 달**에서는 최근 14일 또는 12개월의 학습 행동·자리비움·긍정/차분 단서 추세선을 비교한다. 표의 총평 보기로 해당 날짜나 월의 상세 분석을 연다. **한 시간씩 돌아보기**에서는 선택 날짜의 24개 시간 총평을 펼치고 각 시간으로 이동할 수 있다.

완료된 기간은 바로 전 시간·날짜·월의 전체 구간과 비교한다. 진행 중인 기간은 이전 기간의 같은 경과 구간과 비교한다. 예를 들어 오늘 10:30까지의 기록은 어제 00:00~10:30과 비교한다. 실제 기록의 잘린 마지막 시간도 원본 관찰을 다시 집계하며 시간 평균을 비례 배분하지 않는다. 날짜 경계는 한국 시간(KST)이다. 표본이 부족하면 증감 평가를 보류하고 `—`를 표시한다.

총평은 집계된 수치와 자주 보인 키워드로 만드는 한국어 문장이다. 분석 화면과 총평 생성 자체에서 추가 AI 요청은 하지 않는다. 실제 화면은 보이는 동안 60초 간격으로 갱신한다.

## 집계 기준

카메라 두 대가 같은 사람을 촬영하므로 한 수집 배치의 두 시선을 합친 뒤 10초 구간 하나로 계산한다. 같은 구간의 카메라별 최신 결과를 사용한다. 중복으로 생략한 관찰은 원본 내용을 참조하되 새로 관찰한 시점의 표본으로 반영한다.

| 지표 | 분모와 의미 |
| --- | --- |
| 학습 행동 비율 | **재석 표본** 중 읽기·필기·키보드 입력이 보인 표본. 실제 학습 시간이나 내적 집중력 측정값은 아니다. |
| 자리비움 KPI·추세선 | **관찰된 표본** 중 `seat_empty`가 확인된 표본. 다른 카메라에서 사람이 보이면 재석으로 합친다. |
| 자리 상태 도넛 | **관찰된 표본** 중 재석·자리비움·판단 불가의 비율. 미수집 비율은 별도로 설명한다. API의 `presence` 배열 비율은 미수집을 포함한 선택 구간 전체를 분모로 제공한다. |
| 감정 단서 분포 | **재석 표본 전체** 중 여섯 단서 그룹의 비율. 감정 단서 없음도 포함한다. |
| 긍정·차분 KPI·추세선 | **감정 단서가 있는 재석 표본** 중 긍정·차분 그룹의 비율. 단서가 있는 표본의 커버리지를 함께 표시한다. |
| 데이터 커버리지 | **선택 기간 중 이미 지난 10초 구간** 중 성공 또는 중복 관찰이 남아 있는 비율. |

성공 결과라도 신뢰도가 낮거나 자리 판단 행동이 없으면 **판단 불가**다. 카메라/API 실패와 미수집은 **미수집·누락**으로 구분한다. 자료가 없는 구간을 자리비움이나 학습 실패로 평가하지 않는다. 휴대전화 사용만으로 학습 실패나 산만함을 확정하지 않는다.

## 감정 키워드 추정

사용자가 선택한 **관찰 기록의 감정 키워드 추정**을 적용했다. 관찰 문장과 키워드의 명시적인 표현을 다음 그룹으로 묶는다.

| 그룹 | 예시 |
| --- | --- |
| 긍정·활력 단서 | 미소, 웃음, 기쁜, 의욕 |
| 차분·안정 단서 | 차분, 편안, 평온, 침착 |
| 긴장·어려움 단서 | 불안, 긴장, 짜증, 눈물, 찡그림 |
| 피로·휴식 단서 | 하품, 졸림, 피곤, 눈 비비기, 휴식 |
| 복합 단서 | 같은 표본에 여러 그룹의 표현이 함께 있음 |
| 감정 단서 없음 | 해당 표현을 찾지 못함 |

“미소 없음”, “피곤하지 않다”처럼 뒤따르는 부정 표현을 제외한다. 단순히 책을 읽는다고 차분함을 부여하지 않는다. 이는 설명 가능한 문자열 규칙이며 복잡한 문맥·반어·부정 표현을 모두 이해하지는 못한다. 실제 감정의 확정값이나 로봇 눈 LED 표정 기록이 아니다. 단서가 적으면 높은 긍정 비율이 나와도 전체 재석 상태를 대표하지 않으므로 단서 커버리지를 함께 읽어야 한다.

## 데모 데이터

현재 날짜를 기준으로 12개 달에 걸쳐 시간별 가상 집계를 생성한다. 배포일에는 **359일**이다. 평일·주말, 오전·저녁, 휴식, 피로, 월별 점진적 변화와 일별 편차를 재현한다. 심야에는 학습 표본이 없고 차트의 빈 구간으로 표시한다.

데모의 **오늘은 24시간을 채운 가상 예시**이며 이번 달은 오늘까지만 보여준다. 화면 상단과 각 분석 영역에 DEMO를 표시한다. 가상 집계는 메모리에서만 생성한다. 실제 관찰·총평 테이블에 더미 행을 삽입하거나 외부 AI로 전송하지 않는다. 실제 데이터가 없으면 실제 화면을 빈 상태로 표시하며 데모로 자동 대체하지 않는다.

## 구현과 운영

- `apps/device-dashboard/log_analytics.py`: 집계·비교·총평·가상 데이터와 60초 백그라운드 갱신.
- `apps/device-dashboard/analytics_routes.py`: 읽기 전용 `GET /api/analytics`.
- `apps/device-dashboard/static/analytics.{html,css,js}`: 독립 분석 페이지. 기존 로컬 Pretendard와 SVG를 사용하며 외부 CDN은 필요 없다.
- `/var/lib/300seconds-dashboard/learning.sqlite3`의 `analytics_hours`, `analytics_reports` 테이블에 실제 시간 집계와 시간·날짜·월별 총평을 저장한다. 기존 관찰 스키마 버전 3은 유지한다.

완료 시간도 API 결과가 늦게 도착할 수 있어 두 분 동안 재계산한 뒤 고정한다. 이후의 원본 수정·대량 가져오기를 반영하려면 대시보드를 중지하고 분석 캐시 두 테이블만 초기화한 후 재시작해 다시 집계한다. 원본 `observations`는 유지해야 한다.

```text
GET /api/analytics?source=real&period=day&date=2026-10-25
GET /api/analytics?source=demo&period=month&date=2026-10-01
GET /api/analytics?source=real&period=hour&date=2026-10-25&hour=10
```

잘못된 소스·기간·날짜·시간과 미래 날짜는 HTTP 422로 거부한다. 기존 대시보드의 LAN 접근 범위를 사용한다.

## 배포와 검증

설치 전 실행 중인 대화·수동 장치 시험이 없는 것을 확인하고 관찰 수집을 잠시 멈췄다. 대시보드 서비스만 재시작했으며 별도 관찰 서비스와 펌웨어를 변경하지 않았다. SQLite 일관 백업과 교체 파일 원본은 Nano의 `/var/lib/300seconds-dashboard/backups/log-analytics-egcb__yj`에 있다.

설치 중 실제 관찰 **4,380건을 보존**했고, 수집이 멈춘 상태에서 데모 조회 전후 관찰 수가 같음을 확인했다. 이후 기존 관찰 수집과 자동 눈 표정을 켜진 상태로 복원했다. 후속 읽기 전용 점검에서도 수집 활성, 자동 표정 활성, 눈 상시 표시를 확인했다.

- 로컬 관련 검사 **96개 통과**, Nano의 분석·관찰·자동 눈 검사 **66개 통과**.
- 한국 시간·월말·윤년, 두 카메라 병합, 중복 관찰, 결측/불확실성, 감정 부정 표현, 부분 기간 비교, 총평 저장, 데모 분리를 검사했다.
- 실제 DB에서 시간별 7개·일별 2개·월별 1개 총평 저장을 확인했다. 수집에 따라 증가한다.
- 배포 화면에서 24시간 총평, 14일/12개월 비교, 세 추세선, 상세 이동, 실제/데모 전환을 검사했다.
- 1440·800·390px의 메인/분석 화면에 가로 넘침이 없고 자바스크립트 오류가 없었다.

실측 JSON·배포 manifest·화면 증거는 [검증 자료](dashboard-check/2026-10-25/log-analytics/)에 보관한다.
