# 운영 종료 후 수동 카메라 분석

2026-10-29에 Jetson 보드에 적용했다.

## 현재 동작

- 카메라가 켜져도 주기적으로 GPT 분석을 시작하지 않는다. 서비스 시작마다 저장된 수집 설정과 LEARNING_AUTOSTART 값에 관계없이 자동 수집을 끈다.
- SW5를 약 3.2초 길게 누르면 번호 음성과 0.8초 간격 비프음 네 번을 거쳐 '카메라 영상을 분석하겠습니다'를 재생하고 최신 카메라 프레임을 한 번 분석한다. 기존 설명·키워드 저장 경로를 사용한다.
- 안내 음성은 Typecast로 한 번 생성한 1.922초 캐시다. 버튼을 누를 때 음성 합성 API를 다시 호출하지 않는다.
- 분석 중 중복 요청을 막으며, 안내 재생 실패나 연결 세션 변경, 유효한 카메라 프레임 부재 시 분석을 요청하지 않는다.
- SW1 Live와 SW2 Decisions의 기존 수동 동작을 유지한다. 웹에서 사용자가 명시적으로 연속 수집을 켜는 기능은 남아 있지만 다음 서비스 시작에는 다시 꺼진다.

## 검증과 한계

Jetson의 Python 3.8 환경에서 관련 테스트 72개가 통과했다. 저장된 활성 설정 무시, 안내 후 한 번 요청, 재누름 방지, 안내 실패 시 차단, 기존 버튼 동작을 확인했다. 보드의 observer와 dashboard 서비스를 시작했다. 실제 유료 GPT 분석과 실물 SW5 누름 시험은 수행하지 않았다. 현재 주변장치 연결 상태에 따른 카메라·스피커 동작 확인은 별도다.

배포 전 파일은 보드의 `/opt/300seconds/dashboard/backups/manual-camera-20261029`에 보존했다. API 키와 실제 관찰 DB는 Git 동기화 대상에서 제외한다.

## 함께 처리한 사항

Wi-Fi 주소 자동 선택과 DHCP 변경 시 서비스 재시작을 적용했다. [검증 기록](board-info/2026-10-29/wifi-auto.md)을 참고한다.

NeoPixel을 제거하면 정상 부팅된다는 사용자 실물 확인을 기록했다. Pico 3V3에서 LED 전원을 공급하는 구성의 부하·배선 문제가 유력하다. 종료 순간의 측정값은 없으므로 레귤레이터 과부하와 단락 중 어느 것인지 확정하지 않는다. [전원 진단](board-info/2026-10-29/pico-power/diagnosis.md)을 참고한다.

## 소스 동기화

동작 변경 커밋 `bd0708ccef8d0c454dab91bb7f07d1fccf252ad7`을 GitHub main에 반영하고 Windows와 Jetson 저장소에 맞췄다. Jetson의 기존 변경은 `before-20261029-manual-camera-sync` stash에 보존했다. 운영 경로 `/opt/300seconds/dashboard/app`도 저장소 소스로 맞추고, learning.py·button_audio.py·wifi_network.py·hardware.py·media_worker.py와 안내 WAV의 SHA-256 일치를 확인했다.

서비스 시작 후 12초 간격 상태 확인에서 자동 수집 false, 대기열 0, last_capture null을 확인했다. 이 값은 관측 기간에 캡처 작업이 시작되지 않았다는 증거이며 장시간 또는 실물 버튼 작동 검증을 대신하지 않는다. 원본 진단 로그와 장치별 설정은 Windows에 보관하고 공개 소스와 분리했다.
