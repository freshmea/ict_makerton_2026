# Pico 2 통합 핀 배정과 전원

작성일: 2026-10-23, 한국 시간. 기준은 [통합 펌웨어](../../firmware/pico2-device-bench/README.md), [USB 통합 진단](Pico_Nano_USB_통합_진단.md), [공유 설정](../../crates/pico-device-protocol/README.md)이다. 아래 표는 통합 이미지의 현재 배선 계약이며, 기존 개별 벤치 이미지의 핀표와 혼용하지 않는다.

## 1. 핀 배정

부품면을 위로 보고 USB 커넥터를 위에 놓으면 왼쪽 위가 물리 1번이다. GPIO 번호와 물리 핀 번호를 따로 확인한다. **서보 OE는 물리 16번인 GP12이며, 왼손 NeoPixel 데이터는 물리 21번인 GP16이다.** 두 번호가 같은 핀이 아니다. Pico 2와 Pico 2 W의 아래 외부 헤더 배정은 같다. [공식 핀맵](https://datasheets.raspberrypi.com/pico/Pico-2-Pinout.pdf)

| 부품·신호 | GPIO | 물리 핀 | 통합 펌웨어 설정 |
| --- | --- | --- | --- |
| PCA9685 SDA | GP4 | **6** | I2C0, 100kHz, 7비트 주소 `0x41` |
| PCA9685 SCL | GP5 | **7** | I2C0 |
| 터치 SW1 IO | GP6 | **9** | 입력, PullNone |
| 터치 SW2 IO | GP7 | **10** | 입력, PullNone |
| 터치 SW3 IO | GP8 | **11** | 입력, PullNone |
| 터치 SW4 IO | GP9 | **12** | 입력, PullNone |
| 터치 SW5 IO | GP10 | **14** | 입력, PullNone |
| 터치 SW6 IO | GP11 | **15** | 입력, PullNone, 기본 로컬 진단 선택 |
| PCA9685 OE | GP12 | **16** | HIGH=PWM 출력 비활성, 기존 서보 배정 유지 |
| 왼손 NeoPixel DIN | GP16 | **21** | PIO0 SM0 / DMA0, GRB, 800kHz |
| 오른손 NeoPixel DIN | GP17 | **22** | PIO0 SM1 / DMA1, GRB, 800kHz |
| MAX7219 CLK | GP18 | **24** | SPI0 SCK, mode 0, 1MHz |
| MAX7219 DIN | GP19 | **25** | SPI0 TX, MSB first |
| MAX7219 CS/LOAD | GP20 | **26** | GPIO로 제어하는 공통 CS |
| PCA VCC·터치 VCC | 3V3(OUT) | **36** | 3.3V 로직 전원, 지원 전압·전체 부하 확인 |
| 공통 신호 기준 | GND | 3 등 | PCA·터치·LED·매트릭스·컨버터 GND 연결 |

GP17은 오른손 LED 데이터에 사용하므로 매트릭스 CS를 연결하지 않는다. 매트릭스 CS는 반드시 **GP20 / 물리 26번**이다. USB CDC는 USB 커넥터를 사용하며 UART GPIO를 점유하지 않는다.

| 남겨 둔 자원 | 배정 |
| --- | --- |
| GP0/GP1, 물리 1/2번 | UART 확장용 예약 |
| GP26/GP27/GP28, 물리 31/32/34번 | ADC 확장용 예약 |
| SWD | 전용 디버그 패드 |
| GP23~GP25 | 보드 내부 용도. Pico 2 W 호환을 위해 외부 부품에 배정하지 않음 |

## 2. 전원 분기

7.4V급 배터리에서 **5V 정격 NeoPixel용으로 5.0V로 강하하는 구성은 적절하다.** 컨버터는 배터리의 실제 최대 전압과 필요한 연속 전류를 지원해야 한다. 서보 6V 분기와 LED 5V 분기는 별개로 둔다. 6V를 LED·매트릭스·Pico GPIO에 공급하지 않는다.

```text
배터리 7.4V급
  ├─ 서보용 컨버터 OUT+ 6V ── PCA9685 V+ 나사 단자 ── 서보 빨강 전원
  │                   OUT− ── PCA 전원 GND ──────────── 서보 GND
  │
  └─ LED용 컨버터 OUT+ 5.0V ── 왼손 +5V / 오른손 +5V
                      │       └─ MAX7219 2개 VCC (같은 공급이면 부하 합산)
                     OUT− ── 각 부하 GND

PC 또는 Nano USB ── Pico USB
                     ├─ 3V3 OUT(36) ── PCA VCC + 3.3V 지원 터치 6개 VCC
                     └─ GND ───────── 위 각 GND와 공통 신호 기준
```

**PCA9685 VCC=3.3V는 로직 전원, V+=6V는 서보 전원이다.** OE를 GP12로 연결해도 VCC 전원선은 계속 필요하다. OE에 연결했던 3.3V 직결선과 VCC 전원선을 혼동하지 않는다. PCA IC의 정상 VDD 범위는 2.3~5.5V이며 OE는 active-low이다. [NXP PCA9685 데이터시트](https://www.nxp.com/docs/en/data-sheet/PCA9685.pdf)

서로 다른 컨버터의 **6V OUT+와 5V OUT+를 합치지 않는다.** 별도 5V 컨버터를 여러 개 쓸 때도 출력 병렬 사용이 명시되지 않았다면 양극을 서로 연결하지 않는다. GND는 공통으로 연결한다. 부하 전류는 컨버터에서 각 부품으로 직접 공급·복귀시키고 Pico, 얇은 신호 점퍼, 브레드보드 전원 레일을 서보·LED 주 전류 경로로 쓰지 않는다. 외부 5V를 USB VBUS와 임의로 연결하지 않는다.

## 3. 양손 NeoPixel

사용자 지정 배치는 **한 손 `[4,4,10]`=18개, 양손 합계 36개**다. RGB 3채널 WS2812 계열을 대상으로 하며 RGBW는 현재 이미지의 대상이 아니다.

```text
GP16(21번) ─ 저항 ─ DIN [왼손 4개] DOUT ─ DIN [4개] DOUT ─ DIN [10개]
GP17(22번) ─ 저항 ─ DIN [오른손 4개] DOUT ─ DIN [4개] DOUT ─ DIN [10개]
5V/GND ──────────── 각 손의 전원 입력으로 별도 분기
```

데이터는 첫 픽셀의 **DIN**으로 들어가고 화살표 방향으로 다음 구간에 전달한다. DOUT 쪽에 Pico 데이터를 넣지 않는다. 같은 손의 픽셀 번호는 1~4, 5~8, 9~18이며, 양손은 독립 데이터선이다. `left_segments`·`right_segments`는 USB 설정으로 변경할 수 있다. 현 프레임 용량은 손마다 최대 36개다.

현재 시험은 사용자가 이미 동작을 확인한 **3.3V GPIO 직결** 경로를 유지할 수 있다. 사용자가 보고한 레벨시프터 없는 4개 점등은 그 배선·전압·개체의 관찰이며 36개·긴 배선·전체 부하 조건의 보증은 아니다. 과거 첫 픽셀 전원 단자의 **5.3V 실측 보고**는 과거 관찰값으로 남기며 새 설계의 목표 전압은 **5.0V**다. 신호 인식 문제를 해결하려고 전압을 올리지 않는다. 정확한 LED 칩 리비전이 확인되지 않아 모든 WS2812의 입력 문턱을 하나의 값으로 단정하지 않는다.

프로젝트 기본 부품값은 데이터 직렬 저항 **330~470Ω**을 첫 DIN 가까이에, 전원 입력에는 극성을 확인한 **500~1000µF / 6.3V 이상** 커패시터를 둔다. 전원 없는 LED에 HIGH 데이터를 계속 공급하는 상태를 피하고 데이터선과 GND를 짧게 배선한다. 깜박임·오색·무응답이 있으면 DIN 방향, 공통 GND, 첫/끝 전압, 납땜 도통을 확인하고 5V 전원의 **74AHCT125** 같은 버퍼를 추가하는 경로로 진행한다. [Adafruit 배선 지침](https://learn.adafruit.com/adafruit-neopixel-uberguide/best-practices)

74AHCT125는 3.3V 입력을 받는 TTL 문턱 제품이며 74AHC125와 구별한다. 버퍼 VCC는 5V, GND는 공통, 사용 채널의 active-low OE는 LOW, 입력 A는 Pico, 출력 Y는 LED DIN 방향이다. 전원 핀 가까이에 0.1µF를 둔다. 패키지·모듈의 실제 핀맵을 확인한 뒤 연결한다. [Nexperia 74AHC/AHCT125 데이터시트](https://assets.nexperia.com/documents/data-sheet/74AHC_AHCT125.pdf)

### 전류와 추가 전원 시험

전통적인 RGB 최대 백색 추정치 60mA/픽셀을 적용하면 `36×0.06=2.16A`다. 이는 현품 실측 전류가 아니다. LED 전용 전원은 우선 **5V 연속 3A 이상**을 설계 후보로 두고, 같은 전원에 매트릭스를 연결하면 그 전류도 더한다. 통합 시험의 채널 상한 32/255는 소비를 줄이지만 컨버터 연속 정격·배선 발열·전압 강하의 확인을 대신하지 않는다. 손마다 최대 36개로 확장하면 양손 72개 조건으로 다시 계산한다. [Adafruit 전원 산정](https://learn.adafruit.com/adafruit-neopixel-uberguide/powering-neopixels)

- [ ] **30개 초과 NeoPixel 추가 전원 실부하 시험:** 사용자가 추가한 전원 분기를 포함해 실제 36개를 연결하고, 각 손 첫 픽셀·끝 픽셀의 전압과 컨버터 출력 전압/전류를 기록한다.
- [ ] 같은 5V 공급원에서 각 손으로 +5V와 GND를 함께 분기한다. 끝부분 전압 강하가 크면 같은 공급원의 전원 보강 지점을 추가한 뒤 다시 측정한다.
- [ ] 낮은 밝기 RGB·백색과 서보 동작 전후에 색 변화, 리셋, USB 단절, 전선·커넥터·컨버터 발열을 확인한다. 최대 밝기 시험은 전원 설계와 현품 사양 확인 후 별도 시행한다.

추가 전원선을 연결했다는 보고와 실제 36개 부하 통과는 별개다. 측정값·사용 밝기·점등 수·배선 사진을 새 RUN에 남긴 뒤 체크한다.

## 4. 터치와 매트릭스 전원

터치는 `IO/VCC/GND` 모듈 6개이며 **정확한 품번과 순간/토글 모드는 미확정**이다. 3.3V 구동을 지원하는 현품에 3.3V를 공급하고 IO도 Pico 입력 범위 안인지 확인한다. GPIO는 5V 입력용이 아니다. 현재 입력은 PullNone이므로 연결하지 않은 선의 이벤트를 정상 센서 동작으로 판정하지 않는다. 기본 HIGH=눌림이며 센서별 active-low는 설정 마스크로 바꾼다.

MAX7219 2개는 5V 전원과 공통 GND를 사용한다. 5V MAX7219의 데이터시트 HIGH 입력 최소값은 3.5V라서 Pico 3.3V 직결은 보장 조건을 만족하지 않는다. 사용자의 기존 시험 완료 보고는 유지하되, 제품 구성은 **CLK·DIN·CS 세 선을 AHCT 계열 5V 버퍼로 변환**하는 방식을 권장한다. 매트릭스의 DOUT은 다음 모듈 DIN에만 연결한다. [MAX7219/MAX7221 제조사 데이터시트](https://www.analog.com/media/en/technical-documentation/data-sheets/MAX7219-MAX7221.pdf)

눈 이름은 **기기 본체 기준**이다. 실물 확인 결과 가까운 첫 모듈은 왼쪽 눈, 먼 두 번째 모듈은 오른쪽 눈이다. 정면 미리보기에서는 오른쪽 눈이 화면 왼편에 보인다. 가까운 모듈의 기존 반시계 90도 장착을 유지하며 펌웨어가 `near=CW90(left)`, `far=right`로 한 번만 매핑한다.

상세한 직렬 연결·SW6 동작·점검 항목은 [터치 6개와 양쪽 눈 배선](A_스위치6개_MAX7219_양쪽눈_배선.md)을 따른다.

| 항목 | 현재 근거 |
| --- | --- |
| 서보 주소·기존 배정 | 앞 단계 I2C `0x41`, CH0~CH5 사용자 움직임 확인. [초기 배선 기록](A_Pico2_PCA9685_배선과_초기점검.md) |
| 터치 6개·눈 2개 | 사용자가 마지막 터치·매트릭스 시험 완료라고 확인. 이 문서에서 별도 전기 계측을 수행한 것은 아님 |
| NeoPixel 직결 4개 | 사용자 점등 관찰. 전체 36개 부하·통합 결과로 확대하지 않음 |
| 통합 새 이미지 | 소스와 핀 계약 확인. 실제 업로드·Nano USB·모든 출력 동작은 별도 RUN 필요 |
