# TTS 고정 대기 제거와 연속 API 검증

2026-10-24 17:17 KST 실제 Jetson에서 배포·검증했다. 이 문서의 정책은 앞선 TTS 입력창 추가 기록의 분당 2회·오류 후 고정 차단 설명을 대체한다.

## 공식 한도와 로컬 정책

[Typecast 공식 API 요금 안내](https://typecast.ai/pricing/api/)의 Free 동시 요청 한도는 2개다. 이는 분당 2회 또는 요청 사이 60초 대기를 의미하지 않는다. 예전 코드의 분당 2회, 통신/5xx 실패 후 60초, 인증/429 후 1시간은 이 프로젝트의 로컬 보호 정책이었다.

사용자의 연속 생성 요청에 따라 이 로컬 횟수·고정 대기를 제거했다. 새 명시적 요청은 앞선 생성·재생 완료 후 즉시 보낼 수 있다. 실제 Typecast의 동시 요청·인증·크레딧 오류는 그대로 실패 처리하며 자동 재시도하지 않는다. 한 대의 스피커 재생은 겹치지 않게 순차 처리한다.

**유지한 제한:** 요청당 240자, rolling 24시간 500자, rolling 30일 12,000자, 매 합성 전 계정 포함 크레딧 확인, 유료 플랜 기본 차단. 문자 상한을 올리거나 환경 파일을 바꾸지 않았다. 사용량 장부를 초기화하지 않고 예전 `cooldown_until` 필드만 새 코드에서 0으로 이행한다.

통신 오류는 curl 종료 코드에 따라 DNS·서버 연결·시간초과·TLS·연결 끊김을 구분해 화면에 안내한다. 합성 서비스 로그에는 분류만 기록하며 키나 사용자 문장은 기록하지 않는다. [curl 오류 코드](https://curl.se/libcurl/c/libcurl-errors.html)를 기준으로 분류했다.

## 실제 검증

Rust 검사 2개와 Nano Python 검사 19개가 통과했다. 같은 분의 네 번 연속 예약, 예전 미래 대기 기록, HTTP 0/500/429/401 뒤 고정 차단 없음, 문자 한도 초과 차단 유지, 오류 분류를 확인했다.

대시보드 `POST /api/audio/tts`에 이전 응답을 받은 즉시 다음 요청을 전송했다. 별도 sleep이나 자동 재시도는 넣지 않았다.

| 문장 | 첫 요청 기준 시작 | 생성·재생 소요 | HTTP |
| --- | ---: | ---: | ---: |
| 하나. | 0.000초 | 3.823초 | 200 |
| 둘. | 3.823초 | 4.536초 | 200 |
| 셋. | 8.360초 | 2.687초 | 200 |

합계 **11.048초에 3회 성공**했다. 세 번째 요청은 첫 요청 후 8.36초에 시작됐으며 정상 합성·BA-R9 PCM 재생을 마쳤다. 총 7문자로 기존 장부의 174자는 181자가 됐다. `cooldown_until=0`, 마지막 HTTP 200, 임시 음성 파일 0개다. API·Pico·카메라·마이크 연결 상태는 유지됐으며 기존 별도 Pico fault의 해소를 뜻하지 않는다.

합성 서비스만 재시작했고 대시보드 PID 10055는 유지했다. 배포 중 장부 파일은 그대로였으며 음량과 키 설정도 바꾸지 않았다. 복구 백업은 Nano `/var/tmp/tts-continuous-backup-20261024`다.
