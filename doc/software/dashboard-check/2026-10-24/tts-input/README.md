# 오디오 대시보드 문장 TTS와 음량 개선

2026-10-24. 실제 Jetson 대시보드에 배포하고 BA-R9에서 재생했다. 사용자는 최종 음량을 **“이제 적당함”**으로 확인했다.

## 사용 방법

<http://192.168.184.76:8000/#audio>를 새로고침한다. **문장을 목소리로**에 문장을 입력하고 **TTS 재생**을 누르면 Typecast 서연 음성이 보드의 BA-R9에서 재생된다. 최대 240자이며 Enter는 줄바꿈이다. 합성·재생 중에는 재생 버튼과 다른 스피커 시험 버튼을 잠근다. 완료 또는 실패 뒤에는 입력 문장을 유지하고 다시 사용할 수 있다.

USB 출력은 기존 84%(-6 dB)에서 **92%(-3 dB)**로 올려 ALSA에 저장했다. 시험음은 진폭 0.10에서 0.16으로 약 4 dB 높였다. TTS는 원본 합성 WAV를 48 kHz mono S16으로 변환하고 **+6 dB**를 적용한다. 전체 파형의 최대 피크가 -1 dBFS를 넘으면 적용 증폭량을 낮추며, 마이크의 +12 dB 설정과 독립적이다. 최종 실제 TTS는 +6 dB가 모두 적용됐고 제한기는 동작하지 않았다.

## 검증

- Nano의 실제 Python 3.8 환경: 기존 오디오·Pico·눈 표정·관찰 API를 포함한 40개 회귀 검사 통과. 시험음 조정 후 관련 18개 검사도 통과했다.
- 실제 브라우저: “안녕하세요. 볼륨을 높였습니다. 대시보드의 음성 재생 테스트입니다.” 37자를 입력하고 버튼을 눌러 HTTP 200, Typecast `ssfm-v30` / 서연 합성, `aplay` 성공, 완료 표시, 입력 유지와 다음 요청 가능 상태를 확인했다. 합성 측정값은 5,464 ms다.
- 사용자: 실제 음성을 청취하고 음량이 적당하다고 답했다.
- 추가 합성 없이 모의 응답으로 중복 클릭 방지·`aria-busy`·오류 안내·오류 후 복구를 검사했다. 390px 모바일에서 가로 넘침 없음, 입력 16px, 버튼 높이 48px와 활성화를 확인했다.
- 실제 API: CSRF 누락·외부 Origin은 403, 빈 문장·241자·미지원 필드는 422. 이 검사들은 합성을 발생시키지 않았다.
- 이전 JavaScript 캐시가 새 입력창의 이벤트 연결을 막는 문제를 실제 브라우저에서 발견해 수정했다. 자산 URL에 버전을 넣고 HTML·앱 스크립트·스타일을 재검증하도록 했다.
- 최종 대시보드·TTS 서비스 active, Pico·카메라·마이크 연결을 확인했다. 기존 별도 Pico fault의 해소를 뜻하지 않는다. TTS 임시 WAV가 남지 않고 브라우저/대시보드 프로세스에 Typecast 키가 없음을 확인했다.

## 운영과 복구

합성 전용 `300seconds-tts.service`는 Typecast 키만 root0600 환경 파일에서 전달받는다. 기존 Rust `typecast-sample WAV [TEXT]`와 동일한 `/var/lib/300seconds-runtime/tts-usage.json`을 사용하므로 분당 2회·24시간 500자·30일 12,000자 및 계정 포함 크레딧 제한이 유지된다. 자동 재시도나 별도 유료 플랜을 켜지 않았다. 오디오 장치는 대시보드가 소유하고 합성 서비스는 열지 않는다. 운영 서비스는 문장·WAV를 영구 저장하지 않는다. 이 문서에는 검증용 고정 문장만 기록했다.

앱·바이너리 백업: Nano `/var/tmp/ba-r9-dashboard-tts-backup-20261024`. 음량 변경 직전 ALSA 백업: `/var/tmp/ba-r9-before-volume-increase.state`.
