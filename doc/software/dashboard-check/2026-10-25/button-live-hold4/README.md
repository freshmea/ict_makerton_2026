# SW1 4카운트 확인과 Live 시작·종료 안내

2026-10-25 KST. 누름 즉시 대화가 시작돼 의식하지 못한 기록이 생길 수 있었던 물리 SW1 경로를 제거했다.

현재 조작:

1. 1번을 누른 상태로 0.8초 간격 count를 4회 쌓는다(약 3.2초).
2. “라이브 대화 시작” MP3와 0.6초 660Hz 비프음을 순서대로 재생한다.
3. 두 출력이 성공한 다음 DB 대화 행을 만들고 Live에 연결한다.
4. 손을 떼고 다시 4카운트 길게 누르면 마이크 전송·Live 출력을 중지하고 “라이브 대화 끝” MP3와 0.6초 440Hz 비프음을 재생한다.

각 누름마다 한 번만 동작한다. 1~3카운트, 재연결된 기존 hold, 중복·오래된 입력은 대화를 만들지 않는다. 시작 안내 실패나 안내 중 취소는 DB 대화 행과 외부 세션을 생성하지 않는다. 10분 타이머·대시보드 종료·연결 종료에도 종료 안내를 한 번 재생한다.

## 확인 결과

- Nano Python 3.8 대시보드 회귀 검사 **100개 통과**: [nano-tests.log](nano-tests.log).
- 시작·종료 MP3 2개를 기존 Typecast 서비스로 새로 합성했다. 2~6번 번호 음원은 체크섬을 확인해 그대로 재사용했다. [합성 로그](synthesize.log).
- Nano 실제 ALSA 스피커와 생산 `ButtonAudio` → `Learning.switch_loop` → `Live` 코드를 사용해 연결 순서를 확인했다. 3카운트 중단, 4카운트 시작, 계속 누르기 중 재토글 방지, 새 4카운트 종료, 종료 음성 1회를 모두 확인했다.
- 연결은 가짜 응답으로 대체하고 DB는 별도 임시 파일을 사용했다. 외부 Live API 호출 **0회**, 운영 DB 대화 기록 **시험 전 5건 / 후 5건**이었다. [검증 JSON](verification.json), [스피커 검증 로그](speaker-verification.log).
- 브라우저 실제 화면에서 4카운트·약 3.2초 안내와 대화 준비 상태를 확인했다. 실제 대화 화면이 포함된 `dashboard.png`는 로컬에만 보관한다.
- 기존 연속 관찰 수집은 배포 후 다시 켰으며 800ms 설정을 유지했다.

백업: `/var/lib/300seconds-dashboard/backups/button-live-hold4-20261024T172014Z`. 이전 앱·음원과 SQLite를 보관한다. [배포 메타데이터](deployment.json).

동일 저장소에서 진행 중인 별도의 관찰 DB 변경은 보존했다. Nano에 설치한 Live 코드는 기존 Nano 관찰 저장소와 호환되도록 Live 클래스와 물리 제어 부분을 반영했다. 해당 실행 소스와 검사는 [분리한 실행 소스](isolated-learning.py.txt), [분리한 검사](isolated-test_learning.py.txt)에 기록했다. 관찰 DB 구조나 외부 분석 제공자 코드는 이번 배포에서 바꾸지 않았다.

자동 검증은 물리 GPIO 버튼을 누르는 시험이나 새로운 실제 OpenAI 대화가 아니다. 외부 npm 지침 도구 실행은 자동 승인 검토에서 제3자 코드 실행 위험으로 차단돼 기존 로컬 웹 접근성 지침으로 안내 문구를 검토했다. 기능 구현·배포·검증에는 영향이 없다.
