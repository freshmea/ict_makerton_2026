# RUN-20261023-02 — 서보 펄스 범위 확대와 6축 순차 구동 확인

날짜: 2026-10-23, Asia/Seoul. 관련 작업: A-10·A-11 일부. 직전 시험: [RUN-20261023-01](RUN-20261023-01.md).

결과: 같은 Rust 펌웨어에서 명목 각도 0~180에 대응하는 펄스 범위를 1000~2000µs에서 500~2500µs로 바꾸고, 6개 서보의 순차 구동을 한 차례 수행했다. 사용자는 “회전폭이 커졌고 걸림·이상음 없음”을 확인했다. **500~2500µs는 이번 무부하 벤치에서 관찰한 구동 범위이며, 제조사가 보증한 최대 회전 범위나 실제 0~180도 계측 결과가 아니다.**

## 실제 환경과 변경

| 항목 | 기록 |
| --- | --- |
| Pico·PCA9685·전원·배선 | 직전 RUN과 동일. RP2350, PCA 주소0x41, CH0~CH5. 사용자 보고 전원7.2V→6V; 부하 중 실측 전압·전류 미확인 |
| 서보 | JX CLS6336HV 6개, 명목 서보1~6은 PCA 채널0~5 |
| PC 연결 | USB CDC COM7, protocol=servo-bench-v1 |
| 펌웨어 | [Rust source](../../../../firmware/pico2-servo-bench/src/main.rs), version0.1.0. 이번 RUN은 펌웨어 재빌드·교체 없이 런타임 설정만 변경 |
| 실행 UF2 SHA-256 | `3BA62C47816255FB5A51FFDD972DF67A0506E3E04C3051E0BD13F5D26B73641C` — [build-info.json](../../../../firmware/pico2-servo-bench/dist/build-info.json) |
| Rust·target | Rust1.90.0, thumbv8m.main-none-eabihf |
| 바꾼 값 | `min_us=1000 max_us=2000` → `min_us=500 max_us=2500` |

| 종료 상태 | `state=stopped i2c=ok reason=host_stop oe_high=1` |

시작·종료의 정확한 시각과 소요 시간은 로그에 없으므로 미기록이다. Nano·SD 이미지·카메라·오디오 시험은 이번 범위에 해당하지 않는다.

## 제조사 사양과 이번 설정의 구분

[JX CLS6336HV 제조사 제품 페이지](https://hkjx-servo.com/product-detail.html?category=HOT%20SERVO&product=CLS6336HV)의 원문 데이터에는 중립1520µs와330Hz가 기재되어 있다. 확보한 `text-data.js` 원문은 `.local-tools/jx-cls6336hv-text-data.js`에 있으며, 추출값·원문 해시·SpotMicro 사례는 [조사 문서](../../research/CLS6336HV_SpotMicro_구동자료_조사.md)와 [JSON](../../research/CLS6336HV_SpotMicro_근거데이터.json)에 보존했다. 해당 원문에는 최소·최대 제어 펄스폭이나 최대 회전각이 제시되어 있지 않다.

따라서 제조사 중립값·프레임 주파수 표기를 근거로 500~2500µs 또는 물리180도를 공식 보장값으로 판정하지 않는다. 현재 펌웨어의 명목90도는 두 끝값의 중앙인1500µs로, 제조사 중립1520µs와도 다르다. 물리적 중앙 정렬과 각 축의 사용 가능 범위는 별도 보정 대상이다.

## 수행·판정

| 순서 | 실행·확인 | 실제 결과·증거 |
| --- | --- | --- |
| 1 | 펄스 범위 설정 | 변경 전 Status는1000~2000µs, 이후 `OK CONFIG min_us=500 max_us=2500` — [config.txt](RUN-20261023-02/config.txt) |
| 2 | 구동 직전 상태 조회 | `state=stopped`, `i2c=ok`, 500~2500µs 확인 — [status-before.txt](RUN-20261023-02/status-before.txt) |
| 3 | 명시적 단회 sweep | `OK ARM`·`OK SWEEP` 후 servo1~6 각각 start/end, `EVENT DONE`·`OK STOP` — [servo-sweep.txt](RUN-20261023-02/servo-sweep.txt) |
| 4 | 실물 움직임 확인 | 사용자 관찰: 회전폭 증가, 걸림·이상음 없음. 실제 각도·전류·온도는 계측하지 않음 |
| 5 | 구동 후 상태 조회 | 500~2500µs 유지, `state=stopped i2c=ok oe_high=1` — [status-after.txt](RUN-20261023-02/status-after.txt) |

판정은 **펄스 범위 설정 수락, 순차 PWM 명령 실행, 사용자가 확인한 무부하 움직임**에 한정해 통과다. `EVENT ... angle=180`은 명령 레이블이며 실제 축180도 도달의 센서 증거가 아니다. `oe_high=1` 역시 GPIO 출력 상태로, 실제 OE 전압·기계 정지 지연을 계측한 값은 아니다.

## 재현 명령

저장소 루트에서 아래 명령을 각각 실행한다. `COM7`은 이번 시험 포트이며, 재연결 후에는 목록과 장치 식별 정보를 다시 확인한다. 혼이 주변 물체나 다른 서보와 간섭하지 않는 무부하 배치를 선행한다.

```powershell
& .\tools\pico-servo-bench\target\release\pico-servo-bench.exe --port COM7 config --min-us 500 --max-us 2500
& .\tools\pico-servo-bench\target\release\pico-servo-bench.exe --port COM7 status
& .\tools\pico-servo-bench\target\release\pico-servo-bench.exe --port COM7 sweep
& .\tools\pico-servo-bench\target\release\pico-servo-bench.exe --port COM7 status
```

호스트는 명시적 sweep 때 Arm과200ms heartbeat를 보내고 완료 후 Stop을 보낸다. 원본 로그 네 파일은 수정하지 않고 보관했다. **설정은 RAM에만 유지되므로 Pico 전원 재투입·재부팅 후에는 기본1000~2000µs로 돌아간다.** 재시험 전에 Status로 확인하고 필요한 설정을 다시 전송한다.

## 남은 점검

- 축별 물리 각도·중앙·펄스 범위 측정 및 기구 조립 후 사용 범위 제한.
- 부하 중6V 유지, 전류·발열·컨버터 용량 확인. 이번 무부하 관찰을 부하 구동 보증으로 확대하지 않음.
- USB 단절·heartbeat 만료·명시적 Stop의 실제 정지 및 재연결 시 자동 재동작 방지 시험.
- 네오픽셀·도트매트릭스·터치 센서 단독 시험과 최종 Nano 통합. A 단계 전체 완료로 표시하지 않음.
