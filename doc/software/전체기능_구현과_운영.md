# 전체 기능 구현과 운영

2026-10-24. Rust 실행판의 기능·운영 방법·검증 범위를 기록한다. FastAPI 디바이스 모니터는 계속 disabled 상태다. 새 실행판은 `software/`의 7개 독립 프로세스이며 `300seconds-runtime.target`을 수동으로 시작한다. 부팅 자동 시작은 등록하지 않는다.

## 구현한 기능

| 기능 | 실행 경로 | 제한과 확인 방법 |
| --- | --- | --- |
| 조용한 대기·도움·정정·종료 | controllerd의 명시적 요청, epoch·lease·취소 작업 | 카메라나 모델 판단만으로 먼저 발화/구동하지 않음. 한 턴 뒤 quiet |
| 한국어 힌트 | Gemini 판단+힌트 단일 요청, Rust 행동 gate | 확률0.85는 보정 전 후보값. 낮으면 정해진 확인 질문, 오류면 quiet |
| 외부 판단/생성 선택 | Jev noul, OpenAI Decisions choice, Gemini JSON Schema, OpenAI Responses | Jev/Decisions의 판단과 생성은 별도 단계. 실제 계정 검증과 loopback fixture를 구분 |
| 마이크·로컬 ASR | 실제48k mono PCM→VAD→Vosk small Korean CPU | **로컬 ASR 문장을 먼저 확인**한다. confidence가 높아도 정확성 보장이 아님 |
| 요청한 발화의 클라우드 처리 | `--audio-cloud-consent`와 `--cloud-consent`를 함께 선택한 현재 발화만 Gemini에 전송 | ASR·판단·힌트를 한 번에 처리해 호출을 절약. 원본 연속 스트림은 전송하지 않음 |
| 한국어 음성 출력 | Typecast `ssfm-v30` 한국어 WAV→로컬48k mono S16LE 변환→PCM1→audiod→USB speaker | 최종 힌트 텍스트만 전송. PCM sequence ACK는 큐 수락, 청취/이해 완료가 아님 |
| Stop·말 끼어들기 | 독립 Stop socket, epoch 폐기, native device flush, cloud transport 종료 | VAD barge-in은 `NANO_BARGE_IN=1` 및 `NANO_AEC_VERIFIED=1`을 모두 설정해야 활성화. 실제 동시 발화 성능 확인 필요 |
| 두 카메라·경량 인식 | CSI720p30→320×240 NV12/10fps 슬롯, YOLOX-Nano TensorRT8 FP16, YuNet/OpenCV | 의미 추론은 카메라별 약1초 간격. box/품질/나이와 `present_candidate/unknown`; 신원·감정·집중 판정 없음 |
| CUDA 전처리 | 지속 device buffer/stream, block reduction으로 밝기/움직임 통계 | CPU 참조와 비교. 76,800픽셀 통계는 CPU가 더 빨라 설치판 기본CPU. 의미 추론은 계속CUDA/TensorRT. NVMM→CPU 복사가 있으므로 zero-copy가 아님 |
| 교재 OCR | camerad 독점 유지, 요청 시720p JPEG branch→ROI/회전/품질→Tesseract kor+eng | OCR은 항상 미확인 후보. `confirm-problem`으로 사용자가 확인한 문장만 모델 문맥에 포함 |
| 목표·학습 기억 | SQLite WAL, 명시적 목표, opt-in·확인된 메모·수정·검색·삭제·페이지 export | 모델 추정/음성/사진을 자동 저장하지 않음. 수정도 새 확인을 요구하며 ID/생성 시각 유지, 재확인 시각 갱신. 500메모 한도·응답20개 페이지 |
| 일반 Pico 구동 | protocol v2 Arm/SetPose/SetLight/SetEyes/Outputs/Applied | 보정 범위·속도·밝기 제한, 최신 목표 보간. 기본 서보 잠금, 미연결 matrix 거부 |
| MCU 자체 정지 전파 | Pico disarmed snapshot→picod lease 폐기→controller Stop·audio flush | 실제 터치 미연결. MCU Stop 전파 경로와 실물 터치 입력 시험을 구분 |
| 장애 복구 | controller 사망/lease, 장치 소유 프로세스 종료, 늦은 응답·이전 PCM 거부 | 자동 재연결/과거 동작 재생 없음. 운영자 재시작 후 새 Help 필요 |
| 사용량 제어 | 호출 전 disk ledger 예약, 분당/24시간 상한, 429/5xx cooldown | 실패·취소도 시도로 계산. 자동 재시도/다른 유료 공급자 fallback 없음 |

MediaPipe pose는 현재 Python3.8/JetPack 환경에서 기본 의존성으로 넣지 않았다. 선택한 경량 구현은 실제 Nano에서 빌드한 YOLOX-Nano+YuNet이다. Pose·감정·집중 추론을 구현 성공값으로 꾸미지 않는다. 카메라의 학습자/교재 역할과 ROI는 설치 방향에 맞춰 운영자가 선택한다.

첫 청취 시험에서 espeak-ng 한국어는 사용자가 알아듣기 어렵다고 확인했다. 사용자 선택에 따라 기본 TTS를 **Typecast**로 개정했다. 한국어 `kor`, `ssfm-v30`, 학습 안내용 기본 음성 **서연**(`tc_637cbfeef7f00f21e8a1c6c8`), normal preset을 사용한다. 키·모델 HTTP 요청은 dialogued가 소유하며 controllerd/audiod에는 키를 주지 않는다. Typecast 응답 WAV는 현재 턴 동안만 `/run/300seconds/turn-*`에 두고, 완료/Stop 때 삭제한다. raw 마이크·사진은 TTS로 전송하지 않는다. [공식 TTS 계약](https://typecast.ai/docs/api-reference/text-to-speech/text-to-speech).

로컬 대안 [Supertonic 3 INT8](https://huggingface.co/Supertone/supertonic-3)은 선택 설치용 `setup-neural-tts.sh`로 보존했다. Nano에서 짧은 문장 생성35.73초/RSS 약299MiB를 관측했으며 당시 빌드 작업이 함께 실행됐다. 실시간 기본값으로 선택하지 않는다. 모델은 OpenRAIL-M, sherpa-onnx runtime은 Apache-2.0이며 고정 SHA는 `software/models/supertonic.manifest.json`에 있다. `NANO_TTS_BACKEND=supertonic` 또는 `espeak`는 운영자가 명시적으로 선택하는 로컬 비교 경로다. 자동 fallback은 없다.

## 빌드·설치·시작

```bash
cd ~/ict_makerton_2026
source ~/.local/share/300seconds/rust/env.sh
# 최초 로컬 음성/OCR 환경 및 고정 모델 준비
sudo bash tools/jetson/project-mode.sh
sudo bash software/setup-local-ai.sh
sudo bash software/setup-vision.sh
cargo test --locked --offline --manifest-path software/Cargo.toml -j2
cargo build --release --locked --offline --manifest-path software/Cargo.toml -j2
sudo bash software/install.sh
sudo systemctl start 300seconds-runtime.target
sudo systemctl stop 300seconds-runtime.target '300seconds-runtime@*.service'
```

`setup-vision.sh`는 공식 가중치를 고정 SHA256으로 검사하고 **현재 보드에서** TensorRT 엔진을 생성한다. 생성 시간이 오래 걸릴 수 있다. 모델/엔진을 Git에 넣지 않는다. 설치 파일은 `/opt/300seconds/runtime`, 모델은 `/opt/300seconds/models`, DB/호출 ledger는 `/var/lib/300seconds-runtime`, IPC/일시 자료는 `/run/300seconds`에 둔다. 최초 GStreamer registry 및 TensorRT/CUDA 준비는 데이터가 들어오기까지 수십 초 걸릴 수 있다. `loading_models`, `model_load_ms`와 각 결과의 `observation_age_ms`를 확인한다. cold 첫 추론은 warm 지연보다 길 수 있고 오래된 관측은 unknown이다. picod/audiod/camerad/visiond의 `fresh`와 실제 상태를 확인한 후 사용한다.

## 운영 CLI

같은 service uid만 Unix 제어 소켓에 접근한다. 아래 명령은 **Nano의 Linux 터미널**에서 실행한다.

```bash
study() { sudo -u boarddash python3 /opt/300seconds/runtime/study.py "$@"; }
study status
study goal '내가 고른 수학 문제를 이해하기'
study help '3 곱하기 4를 그림으로 생각하는 힌트 하나만 줘. 정답은 말하지 마.' --cloud-consent --speak
study correct '3 곱하기 4가 아니라 3 곱하기 5 문제야. 힌트만 줘.' --cloud-consent --speak
study stop
study finish
study usage

# 로컬 ASR: 결과를 확인한 뒤 help에 확인/정정한 문장을 넣는다.
study listen
# 명시적으로 허용한 현재 발화만 클라우드에 전송한다.
study listen --audio-cloud-consent --cloud-consent --speak

study ocr --camera 1 --roi 0 0 1280 720 --rotation 0
study confirm-problem 'OCR을 원본과 대조해서 확인한 문제 문장'
study confirm-problem ''  # 확인한 문제 문맥 지우기
study help '이 문제에서 어디부터 생각할지 힌트 하나 줘' --cloud-consent --speak

study memory '{"op":"consent","enabled":true}'
study memory '{"op":"save","text":"내가 선택해서 먼저 읽을 책","confirmed":true,"source":"user"}'
study memory '{"op":"update","id":1,"text":"내가 다시 골라 먼저 읽을 책","confirmed":true,"source":"user correction"}'
study memory '{"op":"search","query":"책"}'
study memory '{"op":"list"}'
study memory '{"op":"export","before":0}'  # next_before가 있으면 그 값으로 다음 페이지
study memory '{"op":"delete","id":1}'
study memory '{"op":"delete_all"}'          # 목표/메모 삭제 및 저장 동의 해제
```

`Ctrl-C`는 CLI에서 controller Stop을 보낸다. 대화는 background job으로 시작하고 `result`로 진행/결과를 확인할 수 있다. `--no-wait`도 지원한다. 정정은 이전 요청을 취소하고 이전 문장+정정 내용을 새 epoch의 인용 자료로 전달한다. Stop/Finish는 현재 문제·정정 문맥을 비운다. 저장한 목표/확인 메모는 별도 삭제 명령 전까지 유지한다.

## 구동·보정

```bash
study arm       # AI 호출 없이 명시적으로 장치 lease/Arm
study light     # 낮은 밝기의 고정 독서 조명
study stop
sudo python3 /opt/300seconds/runtime/calibrate.py --check
# 실물 중심·안전 범위를 직접 확인한 다음에만 보정 파일을 변경한다.
sudo python3 /opt/300seconds/runtime/calibrate.py --channel 0 --range-cdeg 8000 9000 10000 --pulse-us 1000 2000 --confirm-neutral-and-range-tested
sudo python3 /opt/300seconds/runtime/calibrate.py --enable-servos --confirm-neutral-and-range-tested
```

보정 변경은 구동하지 않으며 이전 파일을 백업한다. runtime을 정지/시작한 다음 새 Arm으로 적용한다. **기본 `servo_enabled=false`를 유지**한다. 기존80~100도 범위는 벤치의 명목 시험값이며 기구 결합 후 안전한 범위라는 뜻이 아니다. 모든 축의 중심·방향·min/max pulse·명령각·속도를 확인한 뒤 활성화한다. `pose '[9000,9000,9000,9000,9000,9000]'`의 단위는 절대 centidegree이며 실제 위치 피드백이 없다.

PCA9685는 GP4/SDA(물리6), GP5/SCL(물리7), OE GP12(물리16)이다. 양손 NeoPixel은 GP16(물리21)/GP17(물리22), 터치는 GP6~GP11(물리9/10/11/12/14/15), matrix SPI는 GP18/19/20(물리24/25/26)이다. [핀·전원 문서](Pico2_핀배정_및_전원.md)를 함께 따른다.

출력 I/O는 단일 owner task에서 처리하고 USB RX/TX·touch·5ms safety task를 분리했다. 여러 task가 I2C를 공유하는 대신 최신 목표를 보간하며 I2C timeout을 적용한다. safety task는 lease 만료 시 OE를 즉시 HIGH로 하고, 출력 owner heartbeat가250ms 넘게 갱신되지 않으면 watchdog feeding을 멈춘다. 하드웨어 watchdog은1초다. Bootloader 진입 전에는 watchdog을 중지한다. 독립 servo/LED task를 무조건 늘리는 초기 설계를 이 형태로 개정했다.

protocol v2는 기존 v1 호스트와 교환하지 않는다. [공통 계약](../../crates/pico-device-protocol/README.md)과 최신 Linux updater를 함께 사용한다. 전체 flash 백업은 Nano `tmp/pico-flash/`의0600 파일이며 저장소에 공개하지 않는다.

## API 키·무료 한도

`/etc/300seconds/ai.env`는 root0600으로 두고 **dialogued에만** 전달한다. 저장소의 [빈 예시](../../software/config/ai.env.example)에는 키를 넣지 않는다. `/etc/300seconds/runtime.env`는 모델/로컬 상한 등 비밀이 아닌 기본값이다. 키 파일의 설정이 우선한다. 적용은 `sudo systemctl restart 300seconds-runtime@dialogued.service`이며 진행 중인 턴은 먼저 Stop한다.

```dotenv
TYPECAST_API_KEY=발급받은_실제_키
NANO_TTS_BACKEND=typecast
# 아래 두 값은 보드 runtime.env에 설정되어 있다. 다른 음성을 고를 때만 변경한다.
NANO_TYPECAST_MODEL=ssfm-v30
NANO_TYPECAST_VOICE_ID=tc_637cbfeef7f00f21e8a1c6c8
```

`export`나 `Bearer` 접두어를 넣지 않는다. Typecast 인증은 `X-API-KEY`다. 실제 키로 [subscription API](https://typecast.ai/docs/api-reference/subscription/get-subscription) HTTP200, **Free/15,000크레딧/사용0/동시2**를 최초 확인했다. `usage`는 현재 Typecast 계정 사용량과 로컬 문자 ledger를 함께 보여 준다. 매 합성 전 계정 잔여 포함 크레딧을 조회하고 부족하면 차단한다. 2026-10-24 연속 생성 요청으로 **로컬 분당2회 및 실패 후 고정 대기를 제거**했다. 공식 동시 요청2개는 분당2회 제한이 아니며 새 명시적 요청은 앞선 작업 완료 후 바로 가능하다. 로컬 rolling24시간500문자·rolling30일12,000문자 상한과 실패/취소 예약분은 유지한다. Gemini 호출 상한과 별도다. 자동 재시도·다른 유료 TTS fallback은 없다. 유료 플랜은 기본 차단(`NANO_TYPECAST_ALLOW_PAID=0`)이다.

[Typecast 무료 API 요금](https://typecast.ai/pricing/api/)은 현재 월15,000크레딧, 문자당1크레딧이며 **비상업적 이용 및 출처 표시** 조건이 있다. 이 프로젝트의 시험 음성은 **Typecast AI 합성 음성, 사용 캐릭터: 서연, https://typecast.ai**다. 배포/공개 콘텐츠에서는 [출처 표시 가이드](https://typecast.ai/guideline/)를 적용하고 상업적 제품 이용은 API 플랜을 별도로 확인한다. 웹 Studio 구독과 API 구독은 별개다.

Gemini 공식 문서는 신규 프로젝트에3.5 Flash-Lite/3.8 Flash를 권장한다. 2.5 계열은 과거 사용자 위주로 제한하며 목록 조회 성공이 실제 호출 가능성을 보장하지 않는다. 실제 계정에서2.5 Flash-Lite 호출404와3.5 Flash-Lite countTokens/생성 응답을 확인해 **`gemini-3.5-flash-lite`로 고정**했다. 이 모델은 공식 가격표에 무료 input/output tier가 있다. 무료 데이터의 제품 개선 사용 조건도 확인해야 한다. [모델](https://ai.google.dev/gemini-api/docs/models), [가격/데이터 조건](https://ai.google.dev/gemini-api/docs/pricing).

모델별·프로젝트별 실제 RPM/TPM/RPD와 잔여량은 [AI Studio](https://aistudio.google.com/usage)에서 확인한다. 공식 문서는 공통 고정 무료 한도 대신 프로젝트의 활성 한도 조회를 안내한다. 키를 여러 개 만들어도 같은 프로젝트 한도를 공유한다. [공식 rate limits](https://ai.google.dev/gemini-api/docs/rate-limits). 로컬 기본은 **분당1회·rolling24시간10회**, 출력 최대512토큰, 자동 재시도 없음이다. Gemini 기본은 판단/힌트(허용된 발화는 ASR까지) 한 요청이다. 다른 판단 공급자+생성 공급자는 두 요청을 쓰므로 이 기본 RPM에서는 다음 단계가 차단될 수 있다. 한도를 확인한 후 명시적으로 조정한다.

OpenAI 키는 인증/모델 목록만 확인했다. 공식 Free 등급의 월$100 표시는 **usage limit**이며 무료 크레딧 지급 증거가 아니다. API 키 발급·모델 목록 접근·ChatGPT 구독을 무료 API 추론 사용권으로 간주하지 않는다. 현재 **`NANO_ALLOW_OPENAI_INFERENCE=0` 기본 차단**, OpenAI 생성/Decisions 호출0건이다. [등급/한도](https://developers.openai.com/api/docs/guides/rate-limits), [요금](https://developers.openai.com/api/docs/pricing).

실제 크레딧/과금은 [Billing](https://platform.openai.com/settings/organization/billing/overview), 전체 사용량은 [Usage](https://platform.openai.com/usage)에서 확인한다. Usage/Costs 관리 API에는 별도 admin key 권한이 필요하며 이를 로봇에 요구하거나 설치하지 않았다. [공식 admin API](https://developers.openai.com/api/docs/guides/admin-apis). 크레딧과 비용을 확인하고 사용할 때만 `NANO_ALLOW_OPENAI_INFERENCE=1` 및 공급자 선택을 설정한다. Jev도 별도 TypeSafe 키/계정 확인이 필요하다.

`usage`의 Gemini/OpenAI 부분은 **이 실행판이 시도한 호출**과 마지막 응답 token usage다. 해당 공급자의 다른 앱 사용량·계정 잔여 무료 한도·실제 청구액을 보여 주는 API가 아니다. Typecast 계정 부분만 공식 subscription API를 별도로 조회한다. 재부팅 후 subscription GET에서 **Free15,000 중34 사용/14,966 잔여**를 확인해 로컬34문자 예약분과 일치했다. Gemini 로컬 시도는 실패1회 포함3회이고 OpenAI 추론은0회다. 계정 집계 지연이 있을 수 있으므로 로컬 예약 문자 수를 함께 사용한다. 실패/취소도 상한에서 차감하고 재시작해도 유지한다. 429는1시간, 5xx/전송 실패는1분 cooldown이며 스스로 재시도하지 않는다. HTTP 연결 취소가 공급자 계산/과금 취소를 보장하지 않는다. 기억 삭제도 호출 ledger를 초기화하지 않는다.

실제 Gemini 출력에서 `3×4` 힌트가 “3이3개씩”이라는 잘못된 수량을 제안했다. 이후 프롬프트에 수량 단정을 금지하고, 숫자 리터럴이 있는 힌트를 개념 확인 질문으로 교체하는 결정적 guard를 추가했다. 해당 응답 회귀 fixture와 단위 검사는 통과했다. 변경 후 추가 유료/무료 생성 호출로 정확도를 평가하지는 않았으며, 이 guard가 모든 한국어 수량 표현·계산 오류를 찾아내는 수학 검증기는 아니다. HTTP200·JSON Schema·confidence만으로 교육 내용의 정확성을 보증하지 않는다.

Pico 최종 UF2는155,648바이트, SHA256 `a5548f1b3c63f1e6f7cebd7123f023252d971d09c06f616c7de79068edd5f8d3`다. 전체 flash 백업 후 write/readback/USB application status를 확인했다. [민감 백업을 제외한 결과](board-info/2026-10-24/full-pico-flash.json). 스위치·도트매트릭스 미연결, 기구 결합 후 서보 보정, MCU watchdog starvation 고장 주입, 실제 AEC/double-talk, 다양한 한국어 발화·교재/조명 조건별 정확도는 남은 실물 평가다. 해당 항목을 코드 구현 성공과 혼동하지 않는다.

어댑터 교체 후 설치판 검증에서 Python의 `import numpy`/`import cv2`가 SIGILL로 종료되는 결함을 재현했다. 격리 venv도 system-site-packages의 `/usr/local/lib/python3.8/dist-packages/numpy`를 공유하므로 인터프리터만 바꿔서는 해결되지 않았다. `OPENBLAS_CORETYPE=ARMV8`에서는 같은 OpenCV4.6 import가 성공했다. `local_ai.py`가 NumPy/OpenCV보다 먼저 이 값을 설정하도록 수정해 systemd와 직접 실행에 공통 적용했다. 전역 NumPy·OpenCV 패키지는 교체하지 않았다. 이는 OC 전원 경고와 별도로 재현한 소프트웨어 결함이다. [NVIDIA의 Nano 관련 안내](https://forums.developer.nvidia.com/t/sudo-python3-setup-py-install-illegal-instruction/188607), [NumPy의 CPU dispatch 진단](https://numpy.org/doc/1.25/user/troubleshooting-importerror.html).

설치판에서는 `jetson` 사용자 세션의 PulseAudio가 USB codec의 capture/playback을 먼저 점유해 audiod 시작이 실패하는 별도 결함도 확인했다. 기존 `tools/jetson/project-mode.sh`/`desktop-mode.sh` 전환에 이를 반영했다. 프로젝트 모드에서는 PulseAudio user socket/service의 조건 guard와 client autospawn 비활성화를 적용하고 기존 점유를 해제한다. 데스크톱 복원은 기존 파일·활성 상태를 baseline에서 복원한다. 새 정책의4개 파일이 원래 내용으로 정확히 돌아오고 원래 user socket/service가 active가 된 뒤, 프로젝트 모드를 재적용하면 모두 inactive/ALSA 해제되는 왕복을 실제 확인했다. 기존 baseline과 enable symlink는 보존한다. [왕복 결과](board-info/2026-10-24/full-audio-mode.json). 런타임은 프로젝트 모드에서 사용하고 데스크톱 복원 전 정지한다.

## 전원과 5W 설정

OC 경고 당시와 어댑터 교체 후 재부팅 모두 `nvpmodel -q`는 **5W/ID1**, 저장 파일 `/var/lib/nvpmodel/status`는 `pmode:0001`이었다. CPU0~1 online, 상한921.6MHz, GPU 상한614.4MHz를 확인했다. `/etc/nvpmodel.conf`의 fallback `DEFAULT=0`과 저장한 선택값은 서로 다르며, 이번 관측은 5W가 저장되지 않았다는 증거가 아니다. 전력 모드 설정을 임의로 변경하지 않았다. [저장·실제 상한 증거](board-info/2026-10-24/full-power-persistence.log).

기존 Micro-USB 전원에서 runtime 실행 중40회 입력 전압은 min4624/max4776/평균4726.6mV였고, 모두 정지한 뒤 min4816/max4888/평균4882.2mV였다. 같은 기간 `soctherm: OC ALARM 0x00000001`이 반복됐다. 설치판 첫 검증은 7개 서비스 및 두 카메라 FPS 확인 뒤 SSH 채널이 끊겼다. 전압 저하와 접속 단절의 인과관계는 확정하지 않았다. [당시 부분 결과](board-info/2026-10-24/full-systemd-partial.json), [진단](board-info/2026-10-24/full-power-debug.log).

사용자가 어댑터를 교체한 뒤 재접속했다. 어댑터 표기 전압·전류와 연결 종류는 아직 확인하지 않았다. 새 부팅의 대기 전압50회는 min4808/max4896/평균4888.8mV였고 부팅 직후 OC 경고3건이 있었다. 후속 부하 표본에서도 min4624mV와 OC 경고를 다시 확인했다. 사용자는 **전원 문제는 기록하고 구현·검증을 계속하며 다른 전원을 쓸 수 있을 때 알리겠다**고 지시했다. 전원 안정성을 합격 처리하지 않고 독립적인 소프트웨어 검증을 계속한다. 짧은 표본의 평균값만으로 케이블·순간 전압 강하·장시간 전원 안정성을 보증하지 않는다.

NVIDIA는 Nano용 Micro-USB5V2A 공급 품질과, 주변 장치 부하가 큰 경우 J48 설정을 포함한 배럴잭5V4A 공급을 안내한다. 5W는 CPU/GPU 성능 프로필이며 주변 장치를 포함한 보드 입력 전체를 정확히5W로 제한하는 설정으로 해석하지 않는다. [시작 가이드](https://developer.nvidia.com/embedded/learn/get-started-jetson-nano-devkit), [Nano 사용자 가이드](https://developer.download.nvidia.com/embedded/L4T/r32-2_Release_v1.0/Jetson_Nano_Developer_Kit_User_Guide.pdf), [Nano 전력 프로필 자료](https://info.nvidia.com/rs/156-OFN-742/images/Jetson_Nano_Webinar.pdf).

## 설치판 최종 결과

camera0: 센서30.05/분석10.02fps, camera1: 센서29.86/분석10.02fps. 두720p JPEG의 실제 디코딩과 선택한 CSI crop의 OCR adapter 실행을 확인했다. 실제 교재의 정답/문장 정확도를 평가한 시험은 아니며 후보는 계속 미확인이다. 전체 배경720p OCR은 앞선 시험에서12초 제한에 걸렸고, 요청한 문제 영역을 선택하는 경로로 검증했다.

카메라 소유 프로세스 종료 시 unknown, 재시작 후 새 generation을 확인했다. picod/audio 강제 종료는 controller와 출력 권한을 폐기했고 수동 복구 후 이전 동작을 재생하지 않았다. 이후19회 표본/최소3분 quiet에서7개 PID가 유지됐고 카메라·vision 데이터가 fresh였다. RSS 합계 최대1747.9MiB(프로세스 간 공유 페이지 중복 포함), MemAvailable 최저1788.0MiB, 온도 센서 최대50.0℃,7개 프로세스 CPU 합계 평균56.7%(한 CPU core=100%)를 관측했다. 단기 표본이며 장시간 무고장 보증은 아니다.

시험 전체 입력 전압1479회: min4600/max4840/평균4729.2mV, 추가 OC 경고137건, OOM=False. **기능 검증 통과와 전원 안정성 미통과를 구분**한다. 사용자 지시에 따라 전원 경고로 독립 검증을 막지 않았다. 시험 후7개 runtime은 정지했고 모니터 disabled 및 수동 시작 정책을 유지했다.

PC/Nano 소스의 LF 정규화 SHA256, release/설치 바이너리와 worker·unit 대조, 키 존재 여부/0600 및 실제 키의 소스 포함 검사 결과는 [최종 집계](board-info/2026-10-24/full-final.json)와 [보드 manifest](board-info/2026-10-24/full-final-board.json)에 있다. 이번 확대 검증 자료에는 실제 키·flash 백업·원시 음성·새 카메라 원본·모델 가중치를 추가하지 않았다. 기존20항목 hardware harness는 build12 기록이며, 최종 build13은 기억 수정 추가 후18개 Rust 단위·34개 통합·설치판 검증을 통과한 구성을 기록한다.
