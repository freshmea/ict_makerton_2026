# GPT Decisions 학습 분석과 기기 반응

2026-10-25 KST. Nano 대시보드 **책상 앞의 10초**에 `GPT Decisions · 20장 분석` 버튼을 추가했다. JEV 무료 한도와 기존 GPT 5회 테스트 한도는 유지하고, 별도 운영용 Decisions 경로를 제공한다. 자동 반복 실행하지 않는다.

## 조작

| 입력 | 동작 |
| --- | --- |
| SW1 길게 누르기 | 기존 GPT Live 시작·종료 |
| SW2 짧게 누르기 | 즉시 “이번” 번호 MP3 |
| SW2 길게 누르기 | 번호 음성과 비프음 4회 재생 성공 → 긴 비프음 → 분석 1회 |
| 분석·반응 중 SW2를 새로 길게 누르기 | 분석·반응 취소 |
| 웹의 GPT Decisions 버튼 | 같은 분석·반응 실행 |
| 분석·반응 취소 / Pico 전체 정지 | 대기 반응·재생·모터 중단 |

count 간격은 800ms이고, 4회는 약 3.2초다. 한 번 누른 채 유지해도 반복 호출하지 않는다. 번호·비프음 재생 실패, 오래된 입력, USB 세션 변경은 실행하지 않는다. 실제 물리 스위치 누름 재현은 이번 원격 검증에 포함하지 않았으며, 펌웨어 이벤트부터 4회 소리 완료 후 요청을 만드는 경로는 자동 검사로 확인했다.

웹에서 얼굴·학습 공간 배치를 고른다. SW2는 CAM1/SENSOR0을 얼굴, CAM2/SENSOR1을 학습 공간으로 사용한다. 촬영 중 세대·신선도가 바뀐 카메라는 요청을 실패 처리한다. 올바른 얼굴·책상 배치가 아니면 집중·시선 점수를 보류한다.

## 실행 구조

Pico Rust 펌웨어가 기존 `Pressed/Interval/Released/WindowClosed`를 보내고, 대시보드의 Rust USB 브리지가 이를 전달한다. `300seconds-dashboard.service` 안의 Python `button_audio.py`와 `study_reaction.py`가 소리·요청·기기 반응을 조율한다. 기존 펌웨어 기능을 사용하므로 이번에는 flash를 변경하지 않았다. 브라우저를 닫아도 SW2는 동작한다.

`300seconds-observer.service`는 두 카메라를 1초 간격으로 10쌍, 총 20장 수집하여 서버에 있는 키로 OpenAI `/v1/decisions`를 **한 번** 호출한다. 모델은 기존 Decisions 경로의 `gpt-6-luna`다. 사람 재석, 관찰 가능한 집중·시선 단서, 15개 행동을 같은 구조로 반환한다. 웹 API는 `/api/study/analyze`의 `provider=decisions`, 상태는 `/api/study`, 취소는 `/api/study/cancel`이다. 기존 CSRF 검사를 사용한다.

## 결과별 반응

| 결과 | NeoPixel RGB | 음성 |
| --- | --- | --- |
| 자리 비움 근거 | 보라 160,80,180 | 잠깐 자리를 비웠네요. 돌아오면 하던 공부를 이어 가요. |
| 재석·학습 행동 점수 7 이상 | 초록 35,210,90 | 공부를 이어 가는 모습이 보여요. 지금처럼 한 단계씩 해 봐요. |
| 재석·시선 이탈 단서 | 파랑 40,130,240 | 잠깐 시선이 다른 곳을 향했네요. 준비되면 하던 과제로 돌아가 볼까요? |
| 근거 부족 | 주황 230,155,25 | 지금 화면만으로는 공부 상태를 확인하기 어려워요. 편하게 자세를 잡고 이어 가요. |

알 수 없는 재석을 사용자 정책으로 자리 비움 처리한 경우에도, 음성은 확정적인 자리 비움 표현 대신 근거 부족 문구를 사용한다. 사진만으로 실제 감정이나 내적 집중을 확정하지 않는다. 임의 LLM 출력으로 기기 명령을 만들지 않으며, 정해진 결과 분류와 문구를 사용한다.

기존 Typecast 서비스로 네 문구를 합성하여 `/var/lib/300seconds-dashboard/study-reactions/speech/`에 48kHz/16bit/mono WAV로 캐시했다. 반복 재생에는 TTS API를 다시 호출하지 않는다. 새 합성이 필요하면 기존 Typecast 문자·크레딧 한도를 적용하며 유료 대체 제공자로 전환하지 않는다. 스피커 출력은 `boarddash` 계정의 ALSA `robot_playback`을 사용한다.

서보 **1~4번 / CH0~3**을 각각 마지막 완료 목표각에서 +4° 이동 후 원위치로 되돌린다. 176°보다 크면 -4°로 움직인다. 알려진 목표각이 없으면 중립 90°를 사용하며, 정지 후 펌웨어의 0 초기화 값을 실제 각도로 해석하지 않는다. 기존 개별 서보 제어의 500ms 명령·최대 30°/초·2초 lease·완료 ACK를 사용하고, 반응이 끝나면 Stop으로 출력을 차단한다. NeoPixel은 밝기 24, 800ms 주기로 반응하며 완료 시 소등한다.

Live·수동 서보·다른 스피커 작업 중에는 분석 시작을 거절한다. 반응 중 수동 제어·전체 정지가 요청되면 반응부터 취소한다. 자동 눈 표정은 분석·반응 동안 대기했다가 재개한다. 서보가 준비되지 않았으면 음성·조명만 시도하고 사유를 표시한다. 이미 API로 보낸 분석은 과금될 수 있으나 취소 후 도착한 결과로 기기를 뒤늦게 움직이지 않는다.

완료된 분석 원본·분류·문구·색·4개 서보 명령 완료 여부를 `/var/lib/300seconds-dashboard/study-reactions/<job-id>.json`에 보관한다. 원본 카메라 사진은 이 반응 기록에 저장하지 않는다. 기존 연속 관찰 SQLite 수집은 독립적으로 계속된다.

## 사용량 제한

수동 Decisions 요청은 UTC 하루 최대 200회, 추정 비용 $1.00으로 제한한다. 알려진 사용량은 정산하고 비용이 불명확한 요청은 1회 $0.02를 보수적으로 예약한다. 각 요청 전에도 $0.02를 예약하므로 남은 예산이 이보다 작으면 새 요청하지 않는다. 자동 재시도는 없고 네트워크 오류 후 수동 재요청은 최소 60초 대기한다. 401/402/403 등은 운영 확인 전까지 차단한다. 파일은 observer 상태 폴더의 `decisions-YYYY-MM-DD.json`이며 기존 5회 테스트 파일을 초기화하지 않았다. 이는 로컬 추정 제한이고 OpenAI 계정 전체 지출 제한은 아니다.

[OpenAI Decisions 공식 가이드](https://developers.openai.com/api/docs/guides/decisions)의 비캐시 입력 $0.10/100만 토큰·출력 무료 기준을 사용한다. 실제 청구가 기준이다. 최초 실기 20장 요청은 입력 7,115토큰, 추정 $0.0007115였으며 요청·이미지에 따라 달라진다.

## 검증과 복원

[증거 폴더](dashboard-check/2026-10-25/decisions-reaction/)에 Nano 검사 로그, 배포 정보, 실제 API·기기 반응 상태를 보관한다. 최초 실제 실행에서 20장·요청 1회·API 4.13초·음성 재생 성공·NeoPixel 명령 성공·서보 4개 90→94→90° 완료 ACK·faults 0을 확인했다. 중복 분석과 Live 시작은 모두 409로 차단됐다. 음성 청감·발광·축 실제 각도를 별도 센서로 계측한 결과는 아니다.

최종 각도 기준 보완 후 웹 버튼으로 다시 실행하여 같은 4개 서보 왕복·음성·조명 성공과 오류 없음·정지 완료를 확인했다. 최종 API 응답은 0.78초, 수집부터 기기 반응 종료까지 16.42초, 비용 추정은 동일하게 $0.0007115였다. 두 번 모두 학습 행동·시선 근거 부족으로 점수를 보류했다.

배포 전 설치본·worker·SQLite 백업은 Nano `/var/lib/300seconds-dashboard/backups/decisions-reaction-20261024T193006Z`에 있다. 최종 각도 기준 보완 전 파일은 그 안의 `final-fix/`에 추가 보존했다. 연속 관찰은 배포 후 재개했다.
