### 팀 이름에 담긴 의미

**300초, 단 5분**이라는 짧은 시간 안에 서로 다른 생각을 하나로 융합해 결과를 만들어내겠다는 의미를 담았습니다. 건축학과의 디자인 감각, 컴퓨터공학의 개발력, 재직자의 현실적인 센스와 경험을 모아 실제로 쓸 수 있는 형태까지 빠르게 만들어갑니다.

둘째, 전공이 모두 다릅니다. 그래서 같은 문제를 서로 다른 시각에서 바라볼 수 있습니다.

아이디어만 좋은 팀이 아니라,
디자인하고, 개발하고, 실제로 쓸 수 있는 형태까지 빠르게 만들어내겠습니다.

## 저장소 구조

현재 저장소의 구성입니다.

```text
ict_makerton_2026/
├── README.md                 # 팀 소개, 진행 현황, 협업 안내
├── ict_makerton_2026.ino      # 현재 메인 Arduino 스케치
```

```bash
git clone https://github.com/freshmea/ict_makerton_2026.git
```

5. 컴파일 후 업로드하고, 동작 결과와 재현 절차를 Issue 또는 PR에 남깁니다.

## 협업 방법

### 작업 흐름

**Issue 등록 → 담당자 지정 → 작업 브랜치 → Pull Request → 팀원 검토 → `main` 병합 → 진행 현황 갱신**

1. [Issues](https://github.com/freshmea/ict_makerton_2026/issues)에 작업 목적, 담당자, 마감일, 완료 기준을 기록합니다.
2. 최신 `main`에서 작업별 브랜치를 만듭니다.
3. 작업을 마치면 [Pull Requests](https://github.com/freshmea/ict_makerton_2026/pulls)에 변경 내용과 확인 결과를 작성합니다.
4. 다른 팀원 1명 이상이 검토한 뒤 병합합니다. 충돌이 있으면 관련 작업자와 내용을 확인하고 해결합니다.
5. 병합 후 해당 Issue를 닫고 기능표·일정표·관련 문서를 갱신합니다.

브랜치 이름은 `feat/기능명`, `fix/수정내용`, `docs/문서명`, `design/디자인명` 형식을 사용합니다. 다음은 문서 작업 예시입니다.

```bash
git switch main
git pull --ff-only origin main
git switch -c docs/update-team-info
# 파일 수정 후 변경 내용 확인
git diff
git add README.md
git commit -m "docs: 팀 정보 갱신"
git push -u origin docs/update-team-info
```
