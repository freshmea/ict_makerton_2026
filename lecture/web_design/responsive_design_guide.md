# 모여스터디 반응형 디자인 추가 가이드

이 문서는 [기존 디자인 가이드](design_guide.md)를 보완합니다. 현재 모바일 목록 화면의 색상, 정보, 순서와 기본 간격을 유지하면서, 접힘·펼침·회전·분할 화면·글자 확대에 대응하는 규칙을 정의합니다.

기준 화면은 너비 390px입니다. 이 크기는 검수 기준이며 실제 앱의 고정 너비가 아닙니다. 물리적 디스플레이 해상도 대신 앱에 현재 주어진 공간을 기준으로 배치합니다. 웹에서 아래 px 값은 CSS 픽셀입니다.

## 1. 적용 범위와 우선순위

- 기존 `design_guide.md`는 수정하지 않습니다.
- 두 가이드를 함께 적용할 때 아래 반응형 규칙과 현재 화면에서 확정한 변경 사항을 우선합니다.
- 카드 너비: 기존 `Fixed Contents` 대신 **Fill container**. 카드 높이는 **Hug contents**를 유지합니다. Figma의 실제 고정 크기 설정 명칭은 `Fixed`입니다.
- 버튼 너비: 기존 `Hug contents` 대신 현재 화면처럼 **Fill container**. 높이는 문구와 내부 여백에 따라 **Hug contents**로 설정합니다.
- `모집 인원` 항목 제목: 일정·장소의 항목 제목과 동일한 **13px / Regular / #6B6875**.
- 인원 값(예: `현재 3명 / 정원 6명`): **13px / Semibold / #6C4DFF**.
- 현재 목록의 모든 카드를 대상으로 합니다. 카드 수와 문구를 임의로 변경하거나 중복 카드를 삭제하지 않습니다.
- 새로운 기능 화면은 만들지 않습니다. 다른 너비는 같은 목록의 배치 상태로 다룹니다.

## 2. 유지하는 디자인 값

| 항목 | 유지할 값 |
| --- | --- |
| 화면 배경 | `#F7F7FA` |
| 카드 배경 | `#FFFFFF` |
| 강조색·선택 필터·버튼 배경 | `#6C4DFF` |
| 기본 글자 | `#17151D` |
| 보조 글자·정보 항목 제목 | `#6B6875` |
| 구분선·카드 테두리 | `#E4E2EA` |
| 버튼·선택 필터 글자 | `#FFFFFF` |
| 화면 제목 / 카드 제목 | `24px Bold` / `18px Bold` |
| 본문 / 일정·장소 | `14px Regular` / `13px Regular` |
| 인원 값 / 버튼 문구 | `13px Semibold` / `14px Semibold` |
| 화면 좌우 / 위쪽 여백 | `20px` / `24px` |
| 제목 영역–필터 / 필터–목록 | 각각 `20px` |
| 필터 간격 | `8px` |
| 카드 내부 여백 / 카드 간격 | `20px` / `16px` |
| 카드 내부 요소 간격 / 정보–버튼 | `8px` / `16px` |
| 버튼 좌우 / 상하 내부 여백 | `16px` / `12px` |
| 카드 / 버튼 / 필터 모서리 | `16px` / `10px` / `20px` |
| 카드 테두리 / 그림자 | `1px` / 사용하지 않음 |

현재 한글 글꼴 Noto Sans KR을 유지합니다. Semibold는 600 굵기를 사용하며, 가변 글꼴이면 weight 축을 600으로 설정합니다.

기존 화면 설명과 예시 안내도 유지합니다. 제목과 필터 사이의 20px은 설명을 포함한 제목 영역의 아래쪽과 필터 사이 간격입니다.

## 3. 공간에 따라 변하는 배치

### 기본 원칙

- 요소의 좌표를 고정하지 않고 Auto Layout 또는 웹의 Flexbox·Grid로 배치합니다.
- 화면 너비에 맞춰 목록과 카드 너비를 계산합니다. 여백·글자·모서리를 화면 비율로 일괄 확대하거나 축소하지 않습니다.
- 세로는 내용이 증가하면 늘어나며, 화면보다 길면 세로 스크롤을 허용합니다.
- 화면을 접거나 펼쳐도 선택한 필터와 입력 상태를 유지합니다. 배치 변경을 이유로 데이터를 초기화하지 않습니다.

### 카드 목록의 기준

넓은 화면의 다열 목록에서는 카드 목표 최소 너비를 350px, 열·행 간격을 16px로 사용합니다. 좁은 화면에서는 350px보다 작아지는 것을 허용하여 가로 넘침을 막습니다. 전체 콘텐츠 영역은 좌우 여백을 포함해 최대 1160px이며 중앙에 배치합니다.

| 사용 가능한 화면 너비 | 배치 | 계산 예 |
| --- | --- | --- |
| 390px | 한 열 | 카드 `390 − 20 × 2 = 350px` |
| 320px | 한 열 | 카드 `320 − 20 × 2 = 280px` |
| 756px 미만 | 한 열 | 카드가 좌우 여백을 제외한 너비를 채움 |
| 756px 이상, 1122px 미만 | 두 열 | `350 × 2 + 16 + 20 × 2 = 756px`부터 가능 |
| 1122px 이상 | 세 열 | `350 × 3 + 16 × 2 + 20 × 2 = 1122px`부터 가능 |
| 1160px 초과 | 최대 세 열, 중앙 정렬 | 콘텐츠 최대 너비 1160px 유지 |

이 값은 모여스터디용 배치 기준이며 기종별 해상도 표준이 아닙니다. 별도 패널 안에 목록을 넣을 경우 위 계산은 패널에 주어진 너비를 기준으로 적용합니다. 다열에서도 데이터 순서는 왼쪽에서 오른쪽, 위에서 아래로 유지합니다.

## 4. 카드·텍스트·필터·버튼의 동작

### 카드와 정보 순서

1. 모임 제목
2. 일정
3. 장소
4. 모집 인원
5. `모임 자세히 보기` 버튼

카드 내부 너비는 좌우 여백 40px을 제외한 공간입니다. 웹에서 테두리를 박스 안에 포함하면 테두리 2px도 제외합니다. 예를 들어 350px 카드의 CSS 콘텐츠 너비는 308px입니다. 일정·장소·인원 행은 제목 바로 아래 정보 묶음에 둡니다. 제목–정보 간격은 8px, 정보 행 간격은 8px, 정보 묶음–버튼은 16px입니다.

정보 행의 값은 남은 너비를 채우고 줄바꿈할 수 있어야 합니다. 장소나 일정이 길면 해당 행과 카드 높이가 늘어나야 합니다. 항목 제목을 좁은 고정 높이에 가두지 않습니다. 아주 좁거나 글자가 큰 상태에서 한 행으로 배치하기 어려우면 항목 제목과 값을 위아래로 배치하고, 다음 항목과의 순서를 유지합니다.

### 제목과 글자 확대

- 기본 목록에서는 제목을 최대 두 줄로 표시하고 넘치는 제목에는 말줄임을 사용할 수 있습니다. 원본 제목 문자열을 삭제하거나 변경하지 않습니다.
- 제목이 한 줄에서 두 줄이 되면 제목과 카드 높이가 함께 늘어납니다.
- 전체 제목을 확인할 경로가 없는 화면이나 접근성 확대 상태에서는 줄 수 제한을 풀어 전체 내용을 표시합니다. 정보값은 말줄임으로 숨기지 않습니다.
- 글자 크기를 줄여 억지로 맞추지 않습니다. 웹에서는 기본 글자 크기를 rem으로 표현하고 루트 글자 크기를 사용자 설정에 맞춥니다.
- 이미지처럼 화면 전체를 확대·축소하지 않습니다. 글자, 버튼, 카드가 각각 재배치되어야 합니다.

### 과목 필터

- `전체 → 영어 → 수학 → 코딩` 순서를 유지합니다.
- 390px에서는 현재처럼 한 줄로 표시합니다.
- 좁아져서 네 필터가 들어가지 않으면 **Wrap**으로 다음 줄에 배치합니다. 가로·세로 간격은 각각 8px입니다.
- 줄바꿈이 생기면 필터 영역 높이가 늘어나고 목록은 아래로 이동합니다.
- 필터 문구 자체는 한 줄로 유지하며 선택 상태의 색상을 유지합니다.

### 버튼

- 카드 내부 너비를 채우고 문구는 가운데 정렬합니다.
- 기본 문구는 한 줄로 유지합니다. 문구 수정이나 큰 글자 설정으로 내부 너비를 초과하면 줄바꿈과 높이 증가를 허용합니다. 글자를 자르거나 작게 축소하지 않습니다.
- 좌우 16px, 상하 12px 내부 여백을 유지합니다. 높이를 고정해 글자가 잘리게 하지 않습니다.
- 다른 카드의 높이에 맞추려고 제목과 정보 사이에 임의의 빈 공간을 넣지 않습니다.

## 5. Figma 설정과 검수

| 요소 | 권장 설정 |
| --- | --- |
| 목록을 담는 화면 영역 | 좌우 20px, 위 24px; 가용 너비에 맞춤 |
| 제목 영역 | Vertical; 너비 Fill, 높이 Hug |
| 필터 묶음 | Horizontal + Wrap; 간격 8px; 너비 Fill, 높이 Hug |
| 필터 | 문구와 내부 여백을 확보; 높이는 내용에 따라 증가 가능 |
| 모바일 목록 | Vertical; 너비 Fill, 높이 Hug; 간격 16px |
| 카드 | Vertical; 너비 Fill, 높이 Hug; 내부 여백 20px; 간격 8px |
| 정보 묶음 | Vertical; 너비 Fill, 높이 Hug; 행 간격 8px |
| 정보값 | 너비 Fill, 내용에 따라 높이 증가 |
| 버튼 | 너비 Fill, 높이 Hug; 좌우 16px·상하 12px |
| 버튼 문구 | 기본 한 줄, 중앙 정렬; 확대·긴 문구에서는 재배치 허용 |

정보–버튼 16px을 만들려면 정보 묶음의 아래 여백 8px과 카드의 요소 간격 8px을 조합할 수 있습니다. 두 곳에 각각 16px을 넣어 간격이 중복되지 않게 합니다.

현재 프레임 너비를 320px, 390px, 430px 등으로 바꿔 같은 레이어가 재배치되는지 확인합니다. 목록 콘텐츠는 Hug 높이를 유지하고, 고정 높이 화면 안에서 시연할 때는 세로 스크롤을 설정합니다.

넓은 화면에서 두 열·세 열로 바뀌는 규칙은 Figma에서도 별도 배치 상태로 검증해야 합니다. Auto Layout만으로 CSS의 최소 너비 기반 열 계산이 자동 구현된다고 가정하지 않습니다. 필요한 경우 동일한 목록의 레이아웃 상태를 구성하되 새로운 기능 화면이나 데이터를 추가하지 않습니다.

**Figma 설정은 웹이나 모바일 앱의 실행 코드에 자동 적용되지 않습니다.** 개발 단계에서 같은 규칙을 구현하고 실제 브라우저·기기에서 다시 검수합니다.

## 6. 웹 구현 예시

## 7. 폴더블·회전·분할 화면·키보드 대응

- 화면 너비 변화에 따라 즉시 재배치합니다. 최초 실행 때 확인한 너비를 계속 사용하지 않습니다.
- 가로 모드와 분할 화면에서는 세로 공간이 줄어들 수 있으므로 목록 스크롤을 허용합니다.
- 노치·홈 표시줄 영역에는 중요한 정보와 버튼이 가려지지 않게 안전 영역을 반영합니다. 기본 여백보다 큰 안전 영역이 있으면 필요한 만큼 여백을 늘립니다.
- 웹에서 화면 높이에 맞추는 영역이 필요하면 동적 뷰포트 단위 `dvh` 등을 검토합니다. 목록 전체 높이를 강제로 화면 높이에 맞추지 않습니다.
- 키보드 가림은 `dvh`만으로 해결된다고 가정하지 않습니다. 입력 기능이 추가되면 포커스된 입력칸과 제출 버튼의 가시성을 별도 검수합니다.
- 앱이 실제로 두 화면에 걸쳐 표시되는 경우에는 힌지·화면 분할 영역을 피해 중요한 내용을 배치합니다. 일반적인 한 화면 웹 페이지에도 항상 물리적 힌지 대응이 필요한 것은 아닙니다.

- [ ] 756px과 1122px의 전후 너비에서 열 수가 의도대로 바뀌는가?
- [ ] 프레임 또는 브라우저 너비를 연속으로 변경해도 중간 크기에서 겹치지 않는가?
- [ ] 긴 제목·장소·일정과 긴 영문 문자열에도 정보와 버튼이 겹치지 않는가?
- [ ] 글자 확대 200%에서 정보와 버튼 문구를 읽고 사용할 수 있는가?
- [ ] 좁은 화면에서 필터가 순서를 유지하며 줄바꿈되는가?
- [ ] 회전·분할 화면·접힘·펼침 후 선택한 필터와 상태가 유지되는가?
- [ ] 안전 영역과 필요한 세로 스크롤이 적용되는가?
- [ ] 텍스트·카드·필터·버튼을 각각 편집할 수 있는가?
- [ ] Figma 검수와 실제 웹·기기 검수 결과를 구분해 기록했는가?

기준 크기의 캡처만으로 모든 기기 대응을 완료했다고 판단하지 않습니다. 자동 재배치 규칙, 중간 너비, 긴 데이터, 글자 확대와 실제 기기 상태 변화를 함께 확인합니다.

## 9. 작업 요청 예시

```text
design_guide.md와 responsive_design_guide.md를 함께 적용해줘.
충돌하는 항목은 추가 반응형 가이드를 우선해줘.

390px에서는 현재 디자인과 기본 간격을 유지하고,
화면 너비가 달라지면 목록·카드·버튼이 가용 공간에 맞게 변하도록 해줘.

기존 모임 정보·순서·카드 수는 유지하고 새로운 기능 화면은 만들지 마.
```
